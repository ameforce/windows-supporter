# Codex 사용 한도 초기화 알림 누락 hotfix

## 의도와 변경 분류

- 의도한 계약: 프로필의 사용 한도가 초기화되면 해당 한도의 알림 풍선과 효과음을 한 번 표시한다.
- 현재 동작: 초기화 알림은 저장된 초기화 시각이 지났고, 새 초기화 시각도 수집된 경우에만 생성한다.
- 차이: 현재 사용량이 가득 찼더라도 공급자가 새 초기화 시각을 주지 않으면 알림이 생성되지 않는다.
- 판정: 기존 알림 계약의 감지 누락을 복구하므로 `hotfix/v0.33.11`로 분류한다.

## 근본 원인

프로필의 최신 저장 스냅샷에는 5시간 사용량 `100%`가 있었지만 초기화 시각은 비어 있었고, 효과음 설정은 켜져 있었다. `compute_usage_limit_resets`는 새 초기화 시각이 없으면 즉시 종료하므로 초기화 이벤트가 만들어지지 않았다. 그 결과 기존 알림 전달 경로까지 도달하지 못해 풍선과 소리 모두 나오지 않았다.

## 수정

- 초기화 시각이 확인되면 기존 시간 이동 판정을 우선 사용한다.
- 새 초기화 시각이 없더라도, 이전 초기화 예정 시각이 지난 뒤 잔여량이 완전히 회복된 경우 초기화로 감지한다.
- 초기화 예정 시각도 없는 경우에는 짧은 수집 간격에서 잔여량이 5%p 이상 급증해 99% 이상이 된 상황만 보조 신호로 사용한다.
- 앱 재시작 등으로 초기화 직전 측정값이 없어도, 저장된 초기화 예정 시각이 지난 뒤 처음 읽은 값이 이미 99% 이상이면 예정 시각을 근거로 감지한다.
- 초기화 추론은 병합으로 이전 값이 채워진 스냅샷 대신 현재 응답에서 실제로 파싱된 값을 사용한다.
- 시각 없는 초기화를 감지하면 오래된 초기화 기준을 지워, 공급자가 새 시각을 나중에 제공해도 같은 초기화를 다시 알리지 않는다.
- 설정 화면, 기존 알림 풍선과 효과음 출력은 그대로 사용한다.

## 검증 범위

5시간 사용량 초기화 감지, 초기화 시각이 없는 짧은 급증, 파싱 실패 값의 병합 방지, 작은 변화와 긴 수집 공백의 오탐 방지, 알림 풍선·효과음 1회 전달 및 이후 새 시각 제공 시 중복 알림 방지를 검증한다.
