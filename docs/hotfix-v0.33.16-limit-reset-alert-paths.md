# 사용 한도 초기화 알림 누락(자동 수집 경로와 Claude) hotfix

## 의도와 변경 분류

- 의도한 계약: AI 사용량 프로필의 사용 한도가 초기화되면, 그 한도의 효과음과 알림 툴팁을 한 번 표시한다. v0.33.0(`a662a8c`, "AI 사용 한도 초기화 알림과 효과음 추가")에서 도입했고, v0.33.11 문서도 "프로필의 사용 한도"로 적었다. Claude 프로바이더는 그 전(v0.32.x, `71ff4af`)에 이미 추가되어 있었다.
- 현재 동작:
  - 자동 수집되는 Codex 프로필은 초기화되어도 알림이 나오지 않는다. Codex 7(주간 한도, 9월 23일 13:42 초기화 예정 → 10월 1일로 이동, 99% 남음)의 저장된 초기화 기준값이 여전히 9월 23일에 머물러 있었다.
  - Claude 프로필은 초기화 감지 자체가 없어, 상태 파일에 기준값 항목도 없었다.
- 차이: 초기화 알림 계약이 다중 프로필 자동 수집 경로와 Claude 프로필에서 동작하지 않는다.
- 판정: 기존 계약의 누락과 불완전 구현을 복구하므로 `hotfix/v0.33.16`으로 분류한다.

## 근본 원인

1. **Codex: 저장 경로가 둘이었다.** 초기화 판정과 기준값 갱신, 알림 예약은 `handle_snapshot`에만 있었다. 다중 프로필 관리자의 자동 새로고침과 수동 조회는 각 프로필의 `show_current_status(force_refresh=True)`를 부른다. 이 경로는 수집한 값을 `__commit_merged_snapshot`으로 곧바로 저장해 판정을 건너뛰었다. 그래서 자동 수집 값으로는 기준값도 갱신되지 않고 알림도 나가지 않았다. 기존 시험은 모두 `handle_snapshot`만 호출해 이 경로를 검증하지 못했다.
2. **Claude: 판정이 구현되지 않았다.** 초기화 알림 기능이 `CodexUsageMonitor` 내부에만 구현되어, Claude 모니터에는 기준값 저장, 판정, 효과음, 툴팁이 모두 없었다.

현재 저장 상태로 판정을 돌려 보면, 자동 수집 Codex 프로필 7개 중 5개(7, 1, 2, 3, 4)가 9월 19일~23일 사이 실제 초기화를 알리지 못한 상태였다.

## 수정

- `__commit_merged_snapshot`이 저장할 때마다 초기화 판정, 기준값 갱신, 알림 예약을 함께 하도록 바꾼다. 수집 값을 저장하는 모든 경로가 이 함수를 지나므로, 지금과 앞으로의 어떤 저장 경로도 판정을 건너뛸 수 없다.
- 기준값 갱신 규칙을 모듈 함수 `advance_limit_reset_baselines`로 옮겨 Codex와 Claude가 함께 쓴다.
- Claude 모니터가 수집에 성공한 값을 저장할 때(`_commit_ready_reading`) 같은 판정 함수 `compute_usage_limit_resets`로 5시간·주간 한도 초기화를 감지한다. 수집, 수동 로그인, 로그인 확인이 서로 다른 스레드에서 저장할 수 있으므로 판정과 저장을 잠금으로 묶는다. 기준값은 상태 파일의 `limit_reset_baselines`에 저장하고, 효과음 설정 `limit_reset_sound_enabled`는 설정 파일에 둔다.
- Claude 알림은 새 공용 모듈 `usage_limit_reset_alerts.UsageLimitResetAlert`가 표시한다. Codex와 같은 방식으로 한도별로 합치고, UI 스레드에서 사용자가 다시 입력할 때 효과음과 툴팁을 한 번 보여 준다.

## 배포 후 동작

- 첫 자동 수집에서, 알림이 빠졌던 Codex 프로필 5개가 한 번씩 초기화 알림을 낸다. 이후로는 실제 초기화 때만 알린다.
- Claude는 상태 파일에 기준값이 없으면 저장된 5시간·주간 초기화 시각으로 기준값을 채운다. 저장된 초기화 시각이 이미 지났다면 첫 수집에서 그 한도를 한 번 알린다. 새 창이 시작돼 새 초기화 시각이 보이는 경우와, 아직 새 창이 없어 초기화 시각 없이 사용량이 0%로 돌아온 경우 모두 해당한다. 저장된 값이 이미 초기화 이후 값이면(이번에 보고된 Claude 계정처럼) 지나간 초기화는 소급해 알리지 않고, 다음 초기화부터 알린다.
- Claude의 모델별 주간 한도(`weekly_scoped_limit`)는 공용 판정의 한도 목록에 없어 이번 범위에 포함하지 않는다.

## 검증 범위

- 자동 수집(`auto_monitor`), 수동 조회(`manual_query`), 수동 로그인(`manual_login`) 경로로 저장한 값이 주간 초기화를 한 번만 알리고 기준값을 올리는지 확인한다(수정 전 코드에서 실패).
- Claude의 주간·5시간 초기화 감지, 한 번만 알림, 수동 로그인 경로 감지, 재시작 뒤 기준값 유지와 기준값이 없던 상태 파일에서의 기준값 채우기, 효과음 설정 저장을 확인한다.
- 알림 모듈의 즉시 표시, 입력 대기 후 합쳐 표시, 효과음 끄기, UI 전달 실패 처리를 확인한다.
- Codex·Claude·Cursor 모니터, 다중 프로필 관리자, 초기화 시각 관련 시험을 함께 실행한다.
