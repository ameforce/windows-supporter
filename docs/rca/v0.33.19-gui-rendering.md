# v0.33.19 — GUI 렌더링·연속 크기 변경 RCA

## 계약·범위

기존 계약은 프로필 수가 늘어도 설정 창과 드래그가 정상 반응하는 것이다.
v0.33.18은 교환·알림음·가려진 컨트롤을 복구했지만 네이티브 위젯 수와 반복
레이아웃 비용은 남겼다. 새 기능 정책이 아니라 기존 GUI의 불완전 구현 복구이므로
`hotfix/v0.33.19`로 분류했다. 기준 커밋은 `b6e10e27bf6aaf1d0a112d7cbca673f8686277df`다.

## 원인

1. 프로필마다 네이티브 프레임·컨트롤을 반복 생성했다. 합성 프로필 6개/30개에서
   설정 창의 Tk 위젯 수가 169개/601개였다. 프로필 카드 위치·크기가 바뀔 때
   Windows 자식 창 배치와 재그리기 비용을 반복해서 지불했다.
2. 공통 창의 `<Configure>`마다 내용이 같아도 탭 제목 6개를 다시 설정했다.
   사용자 크기 변경이 자식 배치와 노트북 레이아웃을 반복해서 요청하는 경로였다.
3. 매 크기 변경을 전체 컨트롤의 즉시 재배치로 전파했다. 연속 입력에서 이미
   오래된 중간 크기의 작업까지 실행하여 입력 처리와 최종 화면 정착을 방해했다.

## 구조 수정

- 모든 프로필과 영역을 기존 스크롤 Canvas의 항목으로 그린다. 프로필의 ID,
  변수, 메트릭, 교환 위치는 독립 모델이며 프로필 영역의 네이티브 HWND는 1개다.
- 프로필별 반복 버튼을 상단 고정 조작부 하나로 공유한다. 카드 제목을 선택하면
  해당 프로필의 제공자·수집·작업표시줄·새로고침·연결·삭제를 조작한다.
  삭제 확인, 저장 실패 복원, 표시 한도, 기존 프로필 폴더·설정 형식은 유지한다.
- 제목 드래그와 점유 슬롯 교환은 유지한다. 화면 가장자리 드래그 시 자동 스크롤,
  Escape 취소, Ctrl+위/아래 프로필 선택, 선택 위치 자동 표시를 제공한다.
- 변경된 Canvas 속성과 내용만 갱신하며, 같은 카드의 여러 변경을 한 배치로 합친다.
  위치 이동은 항목별 네이티브 호출 대신 카드 태그의 일괄 이동으로 처리한다.
- 공통 창은 변경된 탭 제목만 쓰고, 연속 크기 변경 중에는 현재 콘텐츠 배치를 유지한다.
  마지막 크기 입력 후 180ms 동안 추가 입력이 없으면 최종 크기로 한 번 재배치한다.
  탭 전환 등 명시적인 자동 크기 맞춤은 지연시키지 않는다. 이 경로는 모든 설정 탭에 적용된다.
- 숨겨짐·파괴·취소 시 예약 작업을 정리한다. 재생성 이전 Canvas나 프로필로 입력을 보내지 않는다.

## 검증과 관측값

같은 Windows 호스트, Python 3.14.7 / Tk 9.0.4, 합성 데이터에서 측정했다.
수치는 부하와 원격 데스크톱 상태에 따라 달라질 수 있으며 보편적인 프레임 보장이 아니다.

| 항목 | v0.33.18 | 최종 v0.33.19 소스 |
|---|---:|---:|
| 프로필 6개 Tk 위젯 수 | 169 | 59 |
| 프로필 30개 Tk 위젯 수 | 601 | 59 |
| 6개 최초 열기 | 1,359ms | 792ms |
| 30개 최초 열기 | 3,292ms | 794ms |
| 6개 최종 크기 배치 중앙값 | 1,448ms | 645ms |
| 30개 최종 크기 배치 중앙값 | 2,416ms | 694ms |
| 연속 크기 변경 시 이벤트 간격 p95 | 1,199ms | 262ms |
| 연속 크기 변경 시 최장 이벤트 간격 | 1,651ms | 420ms |

최종 연속 크기 변경 48회가 콘텐츠 배치 2회로 합쳐졌다. 별도 실제 Tk 마우스
이벤트 회귀 검증의 드래그 motion은 5.947ms, 최초 열기는 654.862ms였다.
교환·보관함 교체·우선순위·취소·단일 HWND·컨트롤 표시 순서 검증을 통과했고 콜백 오류는 0건이다.
`qa_ui_latency.py`는 지연된 콘텐츠 배치도 명시적으로 완료한 뒤 측정한다.
크기 입력이 멈추기를 기다리는 의도적인 180ms 유예 시간은 그 렌더링 수치와 별개다.

직접 영향 테스트 283개 통과. 프로필 보드, 조작 상태, 실제 Canvas bounds,
스크롤 후 hit-test, 선택 교환, 리마운트 정리, 지연 배치, 탭 제목 변경,
기존 설정·드래그·초기화 알림·음소거/중복 방지 계약을 포함한다.

재현 명령:

```text
python -X utf8 -m unittest tests.unit.test_tk_viewport tests.unit.test_profile_board tests.unit.test_codex_usage_ui tests.unit.test_profile_detail_canvas tests.unit.test_ai_usage_taskbar_panes tests.unit.test_main_ui_codex_layout tests.unit.test_main_ui_dashboard tests.unit.test_reset_fanfare tests.unit.test_usage_limit_reset_alerts tests.unit.test_codex_usage_limit_reset
python -X utf8 scripts/qa_ai_usage_drag_regression.py --output-dir <fresh-directory>
python -X utf8 scripts/qa_ui_latency.py --profiles 30 --output <fresh-result.json>
python -X utf8 scripts/qa_ui_interaction.py --repo . --output <fresh-result.json>
```

전체 unit/E2E는 실행하지 않았다. 변경 호출 경로와 관계없는 앱 기능을 추가로
실행하지 않고 공통 창·AI 화면·알림 회귀 범위로 제한했다.
모든 native 데이터는 합성이며 실제 계정의 로그인·설정·프로필을 변경하지 않았다.

## 측정 한계와 제외한 실험

이 수정은 네이티브 위젯 수 증가와 중간 크기 전체 재배치라는 확인된 원인을 제거한다.
Windows 최상위 창 변경과 최종 페인트 자체의 비용이 0이 된다는 뜻은 아니다.
최종 30개 강제 전체 배치 8회 중 최댓값은 1,095ms였다. 60fps나 모든 환경의
무지연을 주장하지 않으며 연속 입력 반응성과 최종 배치 시간을 구분한다.

단순 `root.update()` 시간, 실제 outer mainloop 입력 간격, 최종 이미지 검증은
서로 다른 지표다. 최종 캡처는 소유 창의 PrintWindow로 확인했으며 애니메이션
전체의 프레임 시간이나 스피커 청취를 증명하는 자료로 사용하지 않는다.
기존 fanfare 소스는 변경하지 않았고 회귀 테스트 및 Windows 비동기 API 성공을 확인했다.

OS 레이어/합성 플래그, 테마/폰트 변경, Tcl/Tk DLL 패치, 별도 Python 버전은
진단 실험만 수행했고 배포에는 포함하지 않았다. Windows 전역 그래픽·DPI·RDP·오디오
설정, 설치된 Python/Tk, 사용자 시작프로그램 경로를 바꾸지 않는다.
배포 source/artifact identity와 실행 readiness/canary는 별도 릴리즈 영수증으로 검증한다.
