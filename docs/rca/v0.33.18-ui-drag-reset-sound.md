# v0.33.18: GUI 표시·프로필 드래그·초기화 알림음 RCA

## 분류와 범위

의도한 계약은 정상적인 컨트롤 표시, 움직이지 않는 드롭 대상, 점유 슬롯 교환,
소리 옵션이 켜진 사용량 초기화 알림이다. 현재 구현의 결함·불완전 구현을 복구하므로
hotfix로 분류한다. 변경 전 기준은 v0.33.17 / 01965fa59399acab121bc0e183a038eeaa09be56다.

## 확인한 원인

1. 반응형 행의 위젯을 만든 뒤 형제 프레임을 만들고 `pack(in_=frame)`으로 배치했다.
   geometry host 변경은 stacking order 변경이 아니다. 나중에 만들어진 불투명 프레임이
   체크박스·버튼을 덮었다. 실제 캡처에서도 mapped 상태인 컨트롤들이 빈칸으로 보였다.
   배치 변경 때만 위젯을 프레임 위로 올리고 실제 stacking 순서를 회귀 검증한다.
2. 드래그 안내선을 grid 행에 삽입하고 테두리 두께를 바꾸어 hit-test 대상 자체를 움직였다.
   10개 합성 프로필 재현에서 한 번의 hover로 카드 10개의 bounds가 달라졌다.
   드롭 저장 후에는 탭 전체를 remount하여 카드 10개를 전부 재생성했다.
3. planner는 선택 목록 삽입만 지원했다. 점유 카드를 정확히 교환하지 못했고,
   선택 슬롯 4개가 찬 상태의 보관함 승격은 capacity 오류로 거부했다.
4. 알림음은 `SND_MEMORY | SND_ASYNC`라는 지원되지 않는 조합을 사용했다.
   로컬에서 `RuntimeError: Cannot play asynchronously from memory`를 재현했다.
   예외가 False로 변환되는 동안 독립적인 툴팁 경로는 계속 동작했다.

## 수정

- 드래그 중에는 테두리 색만 바꾸고, 안내선을 `place` overlay로 표시한다.
  같은 대상의 반복 motion에서는 Tk 상태를 다시 쓰지 않는다.
- 카드를 공통 조상 아래 두고 `grid(in_=...)`로 기존 위젯만 이동한다.
  변수·스크롤 컨테이너·포커스를 유지하고 이동 버튼의 경계 상태도 현재 순서에 맞춘다.
- 카드 위에 놓으면 두 프로필만 교환한다. 보관함 프로필을 점유 슬롯에 놓으면
  밀려난 프로필은 원래 보관함 위치로 간다. 카드 사이에서는 기존 삽입·순서 변경을 유지한다.
  전체 4칸이 찬 상태의 보관함→영역 빈틈 드롭은 해당 영역의 가장 가까운 슬롯과 교환한다.
- 최종 release 좌표를 사용하고 pointer grab, Escape/unmap 취소, 드래그 중 상태 갱신 보류를 적용한다.
  저장 실패 시 순서·선택 상태를 복원하고 의도하지 않은 지연 재시도를 취소한다.
- 상세 Canvas의 layout을 합치고, 소멸 때 예약 콜백을 취소한다. 줄바꿈된 텍스트 폭을
  다시 요청 폭으로 돌려주는 피드백을 제거한다. 크기 getter의 중첩 idle pump를 제거한다.
- 같은 탭 알림의 중복 geometry 적용을 막고 즉시 저장·remount 전 autosave 예약을 취소한다.
- 같은 WAV를 프로세스 소유 임시 파일에 한 번 생성하고 `SND_FILENAME | SND_ASYNC`로 재생한다.
  캐시 잠금으로 동시 알림이 미완성 파일을 읽지 않게 한다. Tk가 재생 완료를 기다리지 않는다.
- 선택 한도, 좌우 우선순위, 저장 형식, 프로필 폴더, 초기화 감지·중복 방지·음소거 설정은 유지한다.

직접 영향 테스트 267개 통과. 선택 모듈:

양쪽 우선순위, 모든 점유 슬롯 조합, 보관함 교환, 경계 인덱스, 자기 자신 드롭,
잘못된 대상, 저장 실패 복원, 캐시 재사용·동시 호출·재생 오류를 포함한다.

`python -X utf8 scripts/qa_ai_usage_drag_regression.py --output-dir <evidence-dir>`는
실제 사용자 계정 대신 합성 프로필로 Tk 마우스 이벤트, hover bounds 고정,
위젯 identity/host/row 유지, 가득 찬 영역 교환, 우선순위, 이동 버튼, 취소와 stacking을 검증한다.
최종 native 검증은 반응형 컨트롤 50개, callback 오류 0건이며 모든 동작 assert를 통과했다.
`--play-sound`를 사용한 별도 실행에서 Windows 비동기 재생 호출 성공도 확인했다.
호출 성공은 사용자의 실제 스피커·볼륨·원격 오디오 출력까지 들었다는 뜻이 아니다.
전체 suite/E2E는 실행하지 않았다. 변경 호출 경로와 관계없는 앱·프로바이더 테스트를 확대하지 않았다.
빌드·배포 결과와 source/artifact identity는 별도 release receipt로 기록한다.

## 남은 불확실성과 제외한 실험

이 Windows 환경에서는 독립적인 Tk 창의 단순 Label 200개도 최초 표시·resize에 수 초가 걸렸다.
최종 6개 합성 프로필 native 실행의 hover는 21.416ms였지만 최초 표시는 11.203초였다.
따라서 전체 GUI의 최초 표시·창 크기 변경 지연까지 완전히 없앴다고 주장하지 않는다.
남은 비용 중 Tk, 그래픽 드라이버, 원격 디스플레이, 시스템 부하 각각의 기여도는 확정하지 않았다.

Root compositing/layering, 다른 폰트와 ttk 테마는 합성 진단 창에서만 실험했다.
일관된 이득이 없거나 최초 표시를 악화시켰으므로 배포 코드에 포함하지 않았다.
전역 Windows/RDP/DPI/GPU/오디오 설정과 Python 버전은 바꾸지 않았다.

참고: Python 3.14 공식 `winsound` 문서의 `SND_MEMORY`/`SND_FILENAME` 계약.
