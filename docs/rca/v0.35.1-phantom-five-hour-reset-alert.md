# v0.35.1 — 5시간 한도가 없는 프로필의 5시간 초기화 알림 RCA

## 분류

기준은 `main` f48bcb1128744ab53001e16e227c6faa022813e3 (v0.35.0)이다.

| 의도한 계약 | 확인한 현재 동작 | 판정 |
|---|---|---|
| 사용 한도가 초기화되면 그 프로필의 그 한도에 대해 효과음과 알림 툴팁을 한 번 표시한다(v0.33.0, v0.33.11, v0.33.16, v0.33.17, v0.34.0). 없는 한도의 초기화는 알리지 않는다 | 5시간 창이 없는 Codex Pro 프로필에서 "5시간 사용 한도 초기화됨" 툴팁과 효과음이 간헐적으로 난다 | hotfix (기존 알림 계약의 결함) |

## 증거

- Codex Pro·Pro Lite 요금제는 주간 창만 있다. 로컬 Codex 기록의 `rate_limits`는 `primary.window_minutes=10080`, `secondary=null`이다. Plus만 300분과 10080분 창이 함께 있다.
- 5시간 값이 없는 Codex 프로필의 저장 상태에 5시간 초기화 시각과 기준값이 남아 있었다.
  - `Codex 7`: 5시간 값 없음, 초기화 시각과 기준값 `2026-09-30T02:46:00.000Z`
  - `Codex 2`: 5시간 값 없음, 초기화 시각과 기준값 `2026-09-29T20:52:00.000Z`
  - `Codex 6`, `Codex 1`: 5시간 값 없음, 오래된 5시간 기준값(9/25, 9/26)
  - 5시간 값이 있는 Plus 프로필(`Codex 3`, `Codex 4`)에는 5시간 기준값이 없었다.
- `.000Z` 형식은 페이지 probe의 `Date.toISOString()` 결과다. 즉 이 시각은 웹 페이지 문구에서 나왔다.
- 프로필 브라우저 캐시의 ChatGPT 번들에서 사용 페이지의 한국어 문구를 확인했다.
  - 사용량 한도 재설정 섹션 설명: "재설정을 사용해 5시간 한도, 주간 한도 또는 둘 다를 복원하세요."
  - 재설정 크레딧 만료: "{time}에 만료", 내역: "재설정 받음", "재설정 사용됨"
- 이 문구와 저장 상태를 실제 파싱·판정 함수에 넣어 재현했다. 첫 크레딧이 만료되고 다음 크레딧의 만료 시각이 보이는 관측에서 `five_hour_limit` 초기화가 감지됐다.

## 원인

1. **안내 문장을 5시간 한도 카드로 분류했다.**
   - probe는 별칭을 포함한 짧은 텍스트를 모두 한도 블록으로 보낸다.
   - 분류는 공백을 뺀 토큰으로 가장 긴 별칭을 고른다. 섹션 설명에서 `5시간한도`(5자)가 `주간한도`(4자)보다 길어 `five_hour_limit`이 됐다.
   - 설명 문장에는 값이 없으므로 5시간 값은 비었지만, 페이지가 5시간 한도를 보고한 것으로 기록됐다.
2. **값 없는 블록에 주변 시각을 초기화 시각으로 붙였다.**
   - 초기화 후보 수집은 조상·형제 요소의 "재설정"이 들어간 문구까지 읽는다. 크레딧 만료 시각이 여기서 들어왔다.
   - 다른 한도가 섞인 블록을 막는 검사(`_usage_metric_alias_occurrences`)는 공백을 유지한 채 별칭을 찾는다. 설명의 "주간 한도"가 `주간한도` 별칭과 맞지 않아 다른 한도가 없다고 판단했다.
   - 5시간 시각 검사(±36시간)만 통과하면 크레딧 만료 시각이 5시간 초기화 시각이 됐다.
3. **값이 없는 창도 초기화를 판정했다.**
   - `compute_usage_limit_resets`의 시각 이동 판정은 한도 값이 있는지 보지 않았다.
   - 기준 시각이 지났고 새 시각이 1시간 이상 뒤면 초기화로 알렸다.
   - `advance_limit_reset_baselines`도 값 없는 창의 시각으로 기준값을 만들고 올렸다. 페이지가 더 이상 보고하지 않는 창의 기준값도 지우지 않았다.
   - 병합은 값 없이 보고된 창의 이전 초기화 시각을 최대 36시간 이어 붙였다. 화면에도 "5시간 사용 한도: -" 아래 그 시각이 보였다.
4. **간헐적인 이유.** 크레딧 만료 시각이 36시간 안으로 들어올 때만 5시간 시각으로 받아들여진다. 그 시각이 지나거나 다음 크레딧 시각으로 바뀌면 오탐이 한 번 난다. 오래된 기준값이 남은 프로필은 다음 크레딧 시각이 보이는 순간 오탐이 난다.
5. **Plus에도 영향이 있다.** 설명 블록이 실제 5시간 카드보다 먼저 오면 5시간 초기화 시각을 크레딧 만료 시각이 차지한다. 이때 실제 5시간 초기화를 놓칠 수 있다.

## 수정

- **파서**
  - 두 개 이상의 한도를 언급하는 텍스트는 한도 카드 이름이 아니다. 섹션 설명 같은 문장은 어떤 한도로도 분류하지 않는다. 이름 텍스트로 분류되지 않는 블록의 텍스트가 여러 한도를 언급하면, probe가 같은 방식으로 추정한 `metric_key`도 쓰지 않는다(`_semantic_block_metric_key`).
  - 한도의 초기화 시각은 그 한도의 값을 가진 블록에서만 가져온다. 이름만 있는 블록은 주변 시각을 빌려줄 수 없다.
- **판정과 기준값**
  - 이번 관측에서 값을 측정한 창만 초기화를 판정한다.
  - 기준값은 값을 측정한 관측에서만 만들고 올린다.
  - 페이지가 보고한 창 목록에 그 창이 없고, 직전에 저장한 스냅샷에도 그 창의 값이 없으면 기준값을 지운다. 카드가 한 번 빠진 페이지 하나로는 지우지 않는다.
  - 이름은 있고 값만 일시적으로 없으면 기준값을 그대로 둔다. 다음 정상 관측에서 초기화를 판정한다.
  - 이전 관측의 초기화 시각은 그 관측이 창 값을 측정했을 때만 예정 시각으로 쓴다.
  - 상태 파일에 기준값이 없을 때 저장된 스냅샷으로 기준값을 채우는 규칙도 측정한 창에만 적용한다.
- **병합**: 새 관측과 이전 스냅샷 모두 값이 없는 창에는 이전 초기화 시각을 이어 붙이지 않는다.
- Claude도 같은 판정 함수를 쓴다. 측정한 창만 판정하는 규칙은 같다. Claude 관측은 창 목록을 보고하지 않으므로 창이 없어져도 기준값을 지우지 않는다.

## 배포 후 동작

- Pro 프로필의 첫 조회에서 5시간 창이 보고되지 않고 저장된 스냅샷에도 5시간 값이 없으므로, 남아 있던 5시간 기준값과 표시용 5시간 초기화 시각이 알림 없이 사라진다.
- 이후 크레딧이 만료되거나 새로 생겨도 5시간 초기화 알림은 나지 않는다.
  - 설명이 "5시간 한도"를 별도 요소로 그리면 그 요소는 값 없는 5시간 이름이 된다. 이 경우 오래된 기준값은 남지만 값이 없어 판정하지 않고, 화면에 시각도 붙지 않는다.
- Plus 프로필의 실제 5시간·주간 초기화 알림, 재시작 뒤 감지, 시각 없는 초기화 추론은 유지한다. 달라진 점은 다음과 같다.
  - 값이 파싱되지 않은 관측에서는 판정하지 않고 다음 정상 관측에서 알린다.
  - 같은 이유로 웹 값이 파싱되지 않은 관측에서는 로컬 Codex 값과 결합하지 않는다. 결합은 웹 초기화 시각이 로컬 시각과 2분 안에 맞아야 하는데, 값 없는 카드는 이제 시각을 주지 않는다.
  - 어떤 한도 카드든(5시간, 주간, Spark, 월간) 두 번 연속 빠진 페이지만 받으면 그 창은 없어진 것으로 보고 기준값을 지운다. 그 사이에 실제 초기화가 있었다면 알리지 않는다.

## 검증 범위

- 새 시험 17건 중 16건은 수정 전 코드(f48bcb1)에서 실패한다. 카드가 한 번 빠진 페이지에서도 실제 초기화를 알리는 시험은 수정 전후 모두 통과하는 회귀 방지 시험이다.
  - 섹션 설명 분류, 이름 없는 블록, 값 없는 블록의 초기화 시각, 영문 설명의 주간 시각, 값 없는 카드와 로컬 사용량 결합
  - 값 없는 창의 시각 이동 판정, 기준값 생성·제거·유지, 값 없는 창의 병합
  - 모니터 수준: 크레딧 만료 이동, 수정 전 상태 파일의 기준값 정리, 크레딧 섹션 옆 실제 5시간 초기화, 카드가 한 번 빠진 페이지, 값 파싱 실패 뒤 다음 관측의 알림, "5시간 한도"만 따로 그린 설명
- Codex·Claude 모니터, 다중 프로필 관리자, 초기화 알림, DOM 계약, 로컬 사용량 결합 시험을 함께 실행한다.
- UI가 바뀌지 않았으므로 실제 창을 띄우는 시험과 전체 unit/E2E는 실행하지 않는다.
