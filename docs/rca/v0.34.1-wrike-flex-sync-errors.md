## 1. 기록 없는 주의 `request_failed`

### 원인

- `wrike.log`에서 `Parameter 'nextPageToken' value is invalid`(HTTP 400)가 정확히 주 경계에서 시작했다.
  - 9/14 00:00:01부터 01:46:01까지
  - 9/21 00:00:05부터 9/22 07:24:49까지(31시간)
  - 9/28 00:00:05부터 10:25까지
- 오류는 그 주 첫 timelog가 생긴 순간에 멈췄다(`1 entries`, `7 entries`, `2 entries`).
- 같은 토큰으로 Wrike v4를 read-only로 재현했다.
  - 기록이 없는 trackedDate 범위는 `data: []`, `responseSize: 0`과 함께 45자 `nextPageToken`을 준다.
  - 그 토큰을 따라가면 필터 유무와 관계없이 HTTP 400 `invalid_parameter`가 온다.
  - 여러 페이지 결과(pageSize 20, 58건)에서는 첫 페이지만 `responseSize`(전체 건수)를 준다. 마지막 페이지는 토큰이 없다.
- `__query_authoritative_timelogs_week`은 빈 페이지에서도 토큰을 따라갔다. 400을 받아 `request_failed`로 끝났다. 기존 테스트도 빈 페이지 뒤 두 번째 요청을 기대했다.

### 수정

- 빈 페이지를 받으면 토큰을 따라가지 않는다. 첫 페이지 `responseSize`만큼 모은 뒤에도 따라가지 않는다.
- 첫 페이지가 알린 건수보다 적게 받은 채 빈 페이지가 오면 `invalid_response`로 닫는다. 불완전한 주를 fresh로 캐시하지 않는다.
- 비어 있지 않은 페이지의 토큰 형식 검증, 순환·페이지 한도 검사는 그대로 둔다.

## 2. `Flex error`

### 원인

- 앱의 헤드리스 동기화 경로를 실제 프로필로 재현했다(sync 틱 사이에 실행).
  - `/time-tracking/my-work-record` 요청은 서버에서 307로 `/auth/login?nextUrl=...`에 보내졌다.
  - 결과는 `login_required`였다.
- Flex 프로필의 마지막 인증 활동(IndexedDB, localStorage 활동 시각, 분석 쿠키)은 9/26 01:32:07이었다. 헤드 로그인은 9/19 01:33이었다. Flex 웹 세션이 로그인 7일 뒤 서버에서 만료된 것으로 본다. 이후 모든 5분 동기화가 즉시 로그인 화면을 만났다.
- 앱의 결함:
  - `__apply_flex_sync_result`가 오류 코드를 버리고 메시지만 남겼다. 패널은 내부 상태값 `Flex error`만 보였다.
  - `FlexBrowserError`는 `wrike.log`에 남지 않았다.
  - worker는 `sync` 작업마다 headless를 원한다. 그래서 `Flex 웹 열기`나 초과근무 종료 뒤 자동으로 연 headed 창이 다음 주기 동기화에서 닫혔다. 로그인하던 사람도 예외가 아니었다.
  - 창을 닫은 뒤 다시 `Flex 웹 열기`를 누르면 닫힌 브라우저를 재사용하다 실패했다. 그러면 앱 프로필이 아닌 시스템 브라우저로 열렸다.

### 수정

- Flex 상태에 `error_code`를 남긴다.
  - `login_required`/`login_timeout`이면 패널 동기화 줄에 `Flex 로그인 필요`를 표시한다.
  - 다른 실패는 `Flex error · <code>`로 표시한다.
  - Wrike가 fresh여도 Flex에 문제가 있으면 동기화 줄을 주황(warning)으로 표시한다.
- 로그인 만료를 처음 만났을 때 한 번만 알린다. 알림은 재로그인 경로를 안내한다. 다음 성공 뒤 다시 만료되면 다시 알린다. 수동 동기화는 기존 실패 알림만 쓴다.
- 실패는 코드가 바뀔 때만 `flex sync failed: code=...`로 기록한다. 복구하면 `flex sync recovered after code=...`로 기록한다. 5분마다 같은 줄을 반복하지 않는다.
- 주기·시작 동기화는 사용자가 연 headed Flex 창이 살아 있으면 그 창을 닫지 않고 건너뛴다. 상태는 직전 결과를 유지한다(`loading`에 머물지 않는다).
  - 창이 닫혔는지는 `title()` 왕복으로 확인한다. 실제 Playwright(헤드리스, 임시 프로필)에서 확인했다. 열린 페이지는 True였다. `page.close()` 뒤와 브라우저 프로세스 종료 뒤에는 지연 없이 False였다.
  - 명시적 `지금 동기화`는 지금처럼 창을 닫고 읽는다.
- 창을 닫은 뒤 `Flex 웹 열기`를 다시 누르면 새 headed 브라우저를 연다.

### 운영 메모

- Flex 서버의 세션 만료는 앱이 풀 수 없다. 만료 뒤에는 `Flex 웹 열기`로 다시 로그인해야 한다. 이번 수정은 그 사실을 바로 보이게 하고, 재로그인 창이 중간에 닫히지 않게 한다.

## 검증

- targeted unit: `tests.unit.test_wrike_realtime_progress`, `tests.unit.test_flex_browser_architecture`, `tests.unit.test_flex_worktime`.
  - 새 테스트는 수정 전 코드에서 모두 실패했고(pagination 4 fail + 1 error, Flex 5 fail + 3 error), 수정 후 통과한다.
- 실제 Wrike API read-only 재현: 빈 범위 응답 형태와 토큰 거부, 여러 페이지 `responseSize` 의미.
- 실제 Flex 헤드리스 재현: 307 → `/auth/login` → `login_required`.
- 전체 unit/E2E와 실제 앱 창 실행은 하지 않았다. 변경 호출 경로(권위 timelog 조회, Flex worker/상태 투영, 패널 모델)만 검증했다.
