# v0.35.0 Flex 로그인 창 자동 열기

## 변경 분류

- 의도한 계약: Flex 동기화는 창을 띄우지 않고 백그라운드에서 읽는다. 로그인이 필요하면
  사용자가 설정의 `Flex 웹 열기`로 직접 창을 열어 로그인한다. v0.25.9 계약은 "로그인되지
  않은 headless session은 창을 자동으로 띄우지 않고 `Flex 웹 열기`를 안내한다"이다.
  v0.34.1은 만료를 패널에 `Flex 로그인 필요`로 보이고 한 번 알린다.
- 현재 동작: 계약과 같다. 만료되면 패널에 `Flex 로그인 필요`가 보이고, 알림은 설정 경로를
  안내한다. 사용자가 로그인한 뒤에도 창을 닫고 다음 주기(최대 5분)를 기다리거나
  `지금 동기화`를 다시 눌러야 반영된다.
- 차이: 사용자가 로그인이 필요하면 앱이 Flex 로그인 창을 띄우도록 요청했다(2026-09-28).
- 판정: 창을 자동으로 띄우지 않는다는 기존 계약을 의도적으로 바꾸는 새 제품 정책이므로
  `release/v0.35.0`에서 제공한다. v0.25.9 문서의 해당 문장은 이 문서로 대체한다.

## 동작 계약

- 시작·주기 동기화가 로그인 만료(`login_required`)를 처음 만나면 앱 전용 Flex 로그인 창을
  한 번 연다. 만료가 이어지는 동안 다시 열지 않는다. 동기화에 성공한 뒤 다시 만료되면 다시
  연다. 앱을 다시 시작하면 처음부터 센다.
- 백그라운드에서 여는 창은 앱이 앞으로 가져오지 않는다(`bring_to_front`를 부르지 않는다).
  창 활성화는 Windows 포커스 규칙을 따르며, 툴팁으로 창을 열었다고 알린다.
- 설정의 `Flex 로그인 · 지금 동기화`가 만료를 만나면 로그인 창을 앞으로 가져와 연다.
  - 앱의 로그인 창이 이미 열려 있고 화면에 로그인 단계가 남아 있으면(SSO 페이지, 로그인·인증
    경로, 비밀번호 입력란, 탐색 중) 그 창을 닫았다 다시 여는 대신 앞으로 가져온다.
  - 로그인 단계가 남아 있지 않으면 로그인이 끝난 것으로 보고 창을 닫고 읽는다. 로그인이
    근무 기록이 아닌 페이지에서 끝난 경우의 탈출구다.
  - 사용자가 직접 연 창은 v0.34.1처럼 닫고 읽는다.
- 앱이 연 로그인 창은 로그인이 끝나면 앱이 닫고 바로 동기화한다. 끝남 판정은 페이지가
  근무 기록 URL과 같은 호스트·경로에 있고 비밀번호 입력란이 없는 상태가 1초 간격으로 두 번
  이어지는 것이다. 로그인 창은 근무 기록에서 시작하고, Flex는 로그인 뒤 그곳으로 돌려보낸다.
  근무 기록은 로그인하지 않은 요청을 로그인 화면으로 보낸다. SSO 페이지, 하위 도메인, 인증
  콜백, 로그인 뒤 중간 화면(회사 선택 등), 그 밖의 Flex 페이지에서는 창을 닫지 않는다. 그
  경우 사용자가 창을 닫으면 동기화한다. 창을 연 알림, 설정 화면 안내, 저장된 상태 문구는 모두
  "로그인 뒤에도 창이 남아 있으면 닫아 달라"고 알린다. 성공하면 `Flex 로그인 완료` 툴팁에
  반영한 일수를 보인다.
- 로그인 창이 열려 있는 동안 주기 동기화는 창을 닫지 않고 미룬다. 패널은
  `Flex 로그인 필요`를 유지한다. 미룬 동기화는 읽은 것이 없으므로 실패·복구 로그는 창이
  열리기 전 상태와 비교한다.
- 사용자가 로그인하지 않고 창을 닫으면 바로 한 번 동기화한다. 여전히 만료면
  `Flex 로그인 필요`로 남고, 같은 만료 동안 창을 다시 열지 않는다.
  `Flex 로그인 · 지금 동기화`로 다시 열 수 있다.
- 로그인 완료 뒤 동기화가 다시 만료를 보고하면 창을 다시 열지 않는다. 판정이 틀렸을 때
  창이 반복해서 열리지 않게 하기 위해서다. 툴팁은 `Flex 웹 열기`를 안내한다. 그 창은 앱이
  스스로 닫지 않고, 닫으면 동기화한다.
- 사용자가 `Flex 웹 열기`, 패널의 `Flex 열기`, 초과근무 종료로 직접 연 창은 로그인 후에도
  닫지 않는다. 사용자가 그 창을 닫으면 바로 동기화한다. 이전에는 다음 주기까지 기다렸다.
  열다가 실패해 남은 창도 같다.
- 로그인 창을 열지 못하면 실패 원인에 맞는 안내를 보인다.
  - 네트워크(`navigation_failed`, `browser_timeout`): 네트워크 확인 뒤
    `Flex 로그인 · 지금 동기화`.
  - 앱 브라우저 시작 실패: 앱 재시작 뒤 `Flex 로그인 · 지금 동기화`.
  - 자동 경로는 시스템 브라우저로 대신 열지 않는다. 시스템 브라우저는 앱 전용 프로필과
    세션을 공유하지 않아 동기화가 복구되지 않는다.
- 비밀번호와 SSO 입력은 자동화하지 않는다. 로그인은 사용자가 창에서 직접 한다.

## 구현

- `FlexBrowserClient.open_login_page(activate=...)`: 근무 기록 페이지로 이동한다. Flex가
  로그인 화면으로 보낸다. `activate`일 때만 창을 한 번 앞으로 가져온다.
- `FlexBrowserClient.login_completed()`: 위의 끝남 판정. `title()` 왕복으로 `page.url`을
  갱신한다. 탐색 중인 페이지는 끝나지 않은 것으로 본다.
- `FlexBrowserClient.focus_window()`: 열린 첫 페이지를 앞으로 가져온다.
- `FlexBrowserClient.login_in_progress()`: 다른 호스트(SSO), 로그인·인증 경로, 비밀번호
  입력란, 탐색 중인 페이지가 하나라도 있으면 참이다.
- Flex 브라우저 worker:
  - `login` 작업이 headed 로그인 창을 연다. 사용자가 연 창이 이미 있으면 그 창을 가져가지
    않는다. 명시적 요청이면 그 창을 앞으로 가져온다.
  - headed 창이 있는 동안 1초마다 창 상태를 확인한다. 창이 닫혔거나(`closed`) 로그인이
    끝났으면(`logged_in`) 컨텍스트를 닫고 앱에 알린다. 로그인 끝남 판정은 앱이 연 로그인
    창에만 쓴다.
  - 로그인 창이 열린 동안 미룬 동기화는 `login_pending` 코드로 응답한다.
  - 동기화가 headed 창을 대신하면 `replaced`로 알린다. 원인은 명시적 동기화 또는 확인 전에
    닫힌 창이다. 실행 중인 동기화가 후속이므로 추가 동기화를 시작하지 않는다.
  - 열다가 실패해 페이지가 남은 창은 사용자 창처럼 감시한다. 페이지가 없으면(브라우저 시작
    실패) 클라이언트를 버리고 닫힘으로 보고하지 않는다.
- 앱:
  - 동기화 출처를 `periodic`, `manual`, `after_login`, `window_closed`로 나눠 자동 열기와
    알림을 정한다.
  - 창 이벤트로 시작한 동기화가 진행 중인 동기화와 겹치면 그 동기화가 끝난 뒤 한 번 더
    실행한다.
  - 백그라운드를 멈추거나(대시보드 토글, 종료) Flex를 끄면 이 대기를 버린다. 그 뒤로는
    동기화가 없으므로 앱의 로그인 창도 닫는다(`close_login` 작업). 사용자가 연 창은 남긴다.
    worker가 없으면 새로 띄우지 않는다.
  - 로그인 창을 열기로 한 순간부터 상태에 `login_window_open`을 표시한다. 설정 화면은
    worker가 창을 여는 몇 초 동안에도 기다린다.
- 설정 화면: 로그인 대기 중에는 실패 대신 안내를 보이고 결과를 계속 확인한다(최대 15분).
  도움말 문구를 새 동작에 맞췄다.

## 검증

- targeted unit·e2e: `tests.unit.test_flex_worktime`, `tests.unit.test_flex_browser_architecture`,
  `tests.unit.test_wrike_realtime_progress`, `tests.unit.test_wrike_worktime_panel`,
  `tests.unit.test_settings_ui_threading`, `tests.e2e.test_flex_browser_flow`
  (`RUN_FLEX_BROWSER_E2E=1`).
  - 새 테스트와 바뀐 테스트를 기준 코드(899afbc)에 돌리면 73건이 실패한다(11 fail,
    62 error, 서브테스트 포함). 창 없이 만료를 실패로 보이는 회귀 방지 테스트 1개는 기준
    코드에서도 통과한다.
  - 백그라운드 중지 직전에 큐에 들어간 로그인 작업이 나중에 창을 열어도 알림 없이 닫는지
    확인한다.
- 같은 모듈을 가져오는 `tests.unit.test_google_calendar_unification`의 두 실패
  (`settings_version` 10 != 9)는 기준 커밋에서도 같다. 이번 변경과 관계없다.
- 실제 Chromium(Playwright) 통합: 로컬 fixture 서버가 Flex의 로그인 리다이렉트를 흉내 낸다.
  - worker의 `login` 작업이 창을 열고, fixture가 로그인을 끝내면 `logged_in`을 보고하고
    컨텍스트를 닫는지 확인한다.
  - 페이지를 닫으면 `closed`를 보고하는지 확인한다.
  - 로그인 뒤 중간 화면에서는 끝남으로 보지 않는지 확인한다.
- headed 확인(task 단계, fixture): 실제 headed 창이 열리고 fixture 로그인 뒤 스스로 닫혔다.
  다른 앱이 앞에 있는 동안 연 창은 전경 창을 바꾸지 않았다. 터미널에서 띄운 확인이라 트레이
  앱의 전경 권한과 같지 않을 수 있다. 배포 뒤 실제 만료 상태에서 한 번 더 확인한다.
- 실제 Flex 계정 로그인과 운영 계정 E2E는 실행하지 않는다. 비밀번호·SSO 입력을 자동화하지
  않는 계약이기 때문이다.
