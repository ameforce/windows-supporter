# v0.36.0 휴게 복귀 확인

## 변경 분류

- 의도한 계약: 수동 휴게는 사용자가 근무시간 패널의 `휴게 시작`과 `휴게 종료`로 직접
  기록한다. 진행 중인 휴게는 끝날 때까지 근무시간에서 빠진다.
- 현재 동작: 휴게를 켠 채 자리로 돌아와 종료를 잊으면, 복귀 뒤 일한 시간까지 휴게로
  기록된다. 입력 감지는 출근 확인과 초과근무 자동 일시정지에만 쓰이고 휴게에는 쓰이지 않는다.
- 차이: 사용자가 휴게 중 입력이 한동안 없다가 다시 생기면 휴게 종료 여부를 묻는 화면을
  요청했다(2026-10-14).
- 판정: 기존 의도에 없던 새 사용자 기능이므로 `release/v0.36.0`에서 제공한다. 같은 이유로
  v0.28.0 초과근무 무입력 자동 일시정지도 release였다.

## 동작 계약

- 수동 휴게 중 설정한 무입력 시간 이상 입력이 없다가 입력이 생기면, 근무시간 패널에
  `13:02에 복귀한 것 같습니다. 12:00에 시작한 휴게를 종료할까요?` 카드를 띄운다.
  패널은 기존 자동 표시처럼 입력 포커스를 가져가지 않는다.
- 버튼은 세 개다.
  - `13:02에 종료`: 버튼을 누른 시각이 아니라 입력이 다시 감지된 시각으로 휴게를 끝낸다.
  - `시간 수정`: 휴게 시작 이후이고 현재 이전인 시각을 입력해 그 시각으로 끝낸다. 자정을
    넘긴 휴게는 입력한 시각을 그 범위 안의 가장 최근 날짜로 해석한다.
  - `계속 휴게`: 질문만 닫는다. 다음에 다시 자리를 비웠다 돌아오면 다시 묻는다.
- 답하지 않은 채 패널이 닫히면 질문은 남는다. 패널을 열면 보이고, 다시 자리를 비웠다
  돌아오면 패널을 다시 띄운다. 이때 종료 제안 시각은 처음 복귀한 시각을 유지한다. 다만
  처음 복귀한 뒤 1분 안에 다시 자리를 비웠다면(예: 잠깐 건드린 입력, 화면을 잠그는 키)
  그 입력은 복귀가 아니므로 나중 복귀 시각으로 바꾼다.
- (v0.36.2 보강) 첫 표시를 놓쳐도 질문이 사용자에게 도달하도록, 답하지 않은 질문은 이후
  입력에서 120초 이상 간격으로 패널을 다시 띄운다. 패널이 이미 화면에 있으면 본 것으로
  계산하고, 답하거나 휴게가 끝나면 멈춘다. 자세한 내용은
  `hotfix-v0.36.2-wrike-disabled-hotkey-break-return-resurface.md`를 따른다.
- 화면 잠금 해제도 복귀로 본다. 잠금 해제 때 입력 감지 기준을 새로 잡기 때문이다. 잠금
  화면 입력으로 이미 만든 질문은 잠금 해제 뒤 다시 보여 준다.
- 자리 비움이 휴게 시작보다 먼저 시작됐다면 묻지 않는다. 자리를 비웠다 돌아와 첫 입력으로
  `휴게 시작`을 누른 경우를 복귀로 오인하지 않기 위해서다.
- 질문은 그 질문을 만든 휴게에만 적용한다. 패널 버튼으로 휴게를 끝내거나 새로 시작하면
  질문을 지운다. 다른 휴게가 진행 중이면 이전 질문으로 끝낼 수 없다.
- 입력 감지를 시작할 때 수동 휴게가 진행 중이면 휴게 시작 시각부터 자리 비움을 잰다.
  휴게를 켠 채 PC를 끄고 다음에 켜면 첫 입력에서 묻는다. 휴게 중 앱만 다시 시작돼도
  한 번 물을 수 있다. 진행 중인 휴게가 없으면 입력 감지를 시작한 시각부터 잰다.
- 무입력 기준은 `자리 비움 판단 무입력(분)`(기본 5분, 1~120분)이다. 초과근무 자동
  일시정지와 같은 값을 쓰지만, `무입력 시 초과근무 자동 일시정지`를 꺼도 휴게 질문은
  동작한다. 설정 키(`overtime_idle_pause_min`)는 그대로다.
- `Wrike 자동 알림 활성화`가 꺼져 있거나 백그라운드가 멈추면 묻지 않고, 남은 질문도 지운다.
- 캘린더 휴게와 점심 휴게에는 적용하지 않는다.

## 구현

- `WorktimeStateStore.end_manual_break(end_at, expected_started_at=...)`: 진행 중인 수동
  휴게만 지정 시각에 끝낸다. 휴게를 새로 시작하지 않으며, 시작 시각이 다르거나 종료
  시각이 시작보다 빠르거나 현재보다 늦으면 저장하지 않는다. 저장 실패 시 메모리 상태를
  되돌린다.
- `Wrike`: 활동 감지 콜백에서 직전 입력과의 간격을 재고, 잠금 해제 처리에서 같은 판단을
  한다. 대기 중인 질문은 휴게 시작 시각과 복귀 시각만 메모리에 둔다.
- `WorktimeQuickPanel`: `WorktimeBreakReturnPrompt` 모델과 카드, 시간 수정 편집기를
  추가했다. 질문은 진행 중인 휴게가 있을 때만 모델에 넣을 수 있다.

## 검증 범위

- 상태 저장소 종료 함수의 성공, 거부, 저장 실패 복구를 단위 시험으로 검증한다.
- 복귀 감지, 무입력 기준, 오인 방지, 짧은 입력 뒤 재이탈, 잠금 키와 잠금 해제, 수락과
  수정(자정 넘김 포함)과 계속, 자동 알림 꺼짐, 휴게 중 재시작, 패널 모델 조립을 가짜 화면
  루트로 검증한다.
- 패널 카드의 버튼과 편집기 연결, 제자리 갱신, 모델 검증을 가짜 Tk로 검증한다.
- 변경된 화면은 실제 Tk 시험으로 확인한다. 휴게 복귀 카드 단독과 아침 출근 확인과의
  조합에서 읽기 영역 높이와 하단 버튼이 유지되고, 최악 배치의 기본 폭이 한도 안인지 본다.
- v0.35.11 이후 실패하던 활동 감지 회귀 시험 8개는 시험 준비 코드가 자동 알림 허용 조건을
  만족하지 않던 문제였다. 같은 경로를 바꾸므로 준비 코드를 맞춰 함께 통과시킨다.
- 전체 시험 모음과 앱 실행 E2E는 실행하지 않는다. 직접 소비 모듈 14개만 실행한다.
