# v0.37.0 Codex API 크레딧 잔액 릴리스

## 변경 개요

- Codex 프로필이 쓰는 브라우저 프로필에서 OpenAI Platform 결제 개요 페이지(`https://platform.openai.com/settings/organization/billing/overview`)의 API 크레딧 잔액(`Credit balance`)을 읽어 Codex 사용량 옆에 표시한다.
- 표시 위치는 네 곳이다.
  - AI 사용량 설정의 Codex 프로필 카드: `API 크레딧 잔액`, `API 잔액 확인` 행
  - 같은 화면의 실시간 상태 영역: 같은 두 항목
  - 사용량 조회 알림 툴팁: `API 크레딧 잔액:` 줄
  - 작업표시줄 오버레이: 지표 조각에 마우스를 올렸을 때의 `API 크레딧 ...` 줄
- 작업표시줄 compact 행에는 새 슬롯을 만들지 않는다. 폭 배분 엔진을 바꾸지 않고, 달러 잔액은 호버 툴팁으로만 보여 준다.
- `남은 크레딧`(ChatGPT 크레딧, 오버레이 `CR`)과 API 크레딧은 서로 다른 값이다. 화면에서는 이름으로 구분하고 API 잔액은 달러 금액으로만 표시한다.

## 분류 근거

- 의도한 계약: Codex 사용량은 chatgpt.com 사용량 페이지의 한도와 ChatGPT 크레딧만 수집·표시한다. 저장소의 코드와 문서에는 `platform.openai.com`, 결제 개요, API 잔액에 대한 계약이 없다.
- 현재 동작: API 크레딧 잔액을 수집하지 않는다.
- 차이: 새 데이터 출처와 새 사용자 표시를 도입한다. 누락된 의도의 복구가 아니라 새 기능이다.
- 판정: 릴리스 차선(`release/v0.37.0`, 기준 `develop`).

## 수집 경계

- API key를 쓰지 않고 쿠키를 복사하지도 않는다. 앱이 관리하는 Codex 프로필의 headless Chrome에서 사용량 조회가 확정된 직후 별도 탭으로 결제 개요 페이지를 한 번 열어 읽고 닫는다. 사용량 탭은 그대로 둔다.
- 수집 주기는 성공 후 600초, 실패 후 300초, 로그인 필요 후 1800초다. 앱을 다시 켜거나 작업 프로세스를 계획대로 재활용하면 첫 조회부터 읽는다. 시간 초과 등으로 강제 종료한 작업 프로세스를 대신한 경우에만 그 프로세스의 첫 조회에서 읽지 않는다(세션이 새 드라이버에 넘긴다). 멈춘 페이지가 원인이어도 재시도가 사용량부터 얻게 하기 위해서다.
- 한 번의 조회가 쓸 수 있는 시간 안에서만 읽는다. 세션 제한(90초)은 명령을 넣을 때부터 재지만 작업 프로세스는 자기 안의 시간만 알 수 있다. 그래서 프로세스 재활용·생성, 프로필 잠금 재시도에 쓴 시간까지 감안해 30초를 남기고, 사용량 조회가 작업 프로세스 안에서 54초를 넘기면 이번에는 건너뛴다. 읽기 단계는 최대 15초다. 이 단계의 실패와 예외는 Codex 사용량 결과와 브라우저 상태에 영향을 주지 않는다.
- 렌더된 본문 텍스트에서 `Credit balance`(또는 `크레딧 잔액`)로 시작하는 줄을 찾고(이 제목이 없는 화면에서만 `Available credit` 같은 동의어를 본다), 같은 줄이나 바로 아래 줄의 달러 금액만 인정한다. 동의어는 결제 개요 경로에서만 인정한다. 라벨과 금액 사이의 `Add to credit balance` 같은 버튼 줄은 최대 2줄까지 건너뛰되 알려진 버튼 문구와 줄 전체가 일치할 때만 건너뛴다. 모르는 문구 아래 금액은 읽지 않는다. `$1,23`처럼 금액 뒤에 숫자가 이어지면 잘라 읽지 않는다. 예산, 자동 충전 기준 금액, 라벨 위쪽의 금액은 인정하지 않는다. 읽지 못하면 다른 값을 추측하지 않고 `조회 불가`로 둔다.
- 로그인은 ChatGPT 로그인과 별개다. 로그아웃 상태로 결제 개요 주소를 열면 자동 로그인 없이 `platform.openai.com/login`이 나타난다. 이때 상태는 `로그인 필요`가 된다.
- 프로필 카드 메뉴의 `API 크레딧 연결`은 같은 프로필의 로그인 창을 결제 개요 주소로 연다. 사용자가 직접 로그인하면 잔액이 보이는 즉시 창이 자동으로 닫히고 headless 수집으로 돌아간다. 대기 시간은 최대 10분이며 창을 닫으면 바로 끝난다. 로그인 후 결제 개요에서 잔액을 연속 4번 찾지 못하면 기다리지 않고 창을 닫고 그렇게 안내한다. 로그인 뒤 다른 플랫폼 화면에 도착하면 결제 개요로 되돌리되 같은 경로에서는 최대 2번, 한 번의 연결에서 모두 6번까지만 되돌린다. 로그인 창을 기다리는 동안 상태는 `API 크레딧 로그인 대기 중`으로 표시한다. 앱은 자격 증명을 입력하거나 저장하지 않는다.
- 로그인 창이 열려 있는 동안에는 수집 잠금을 쥐어 Codex 조회와 겹치지 않는다. 연결 해제, 프로필 삭제, 앱 종료는 취소 신호로 로그인 대기를 먼저 끝낸다.

## 저장 형식

- `codex_usage_state.json`의 `last_snapshot`에 `api_credit_balance`, `api_credit_captured_at`, `api_credit_status`(`ok`, `login_required`, `unavailable`)가 추가된다. 스냅샷 계약 버전은 올리지 않으며 이 키가 없는 이전 파일은 빈 값으로 읽는다.
- 이 값들은 사용량 지표가 아니다. 사용량 이력, 변경 알림, 한도 초기화 감지, 사용 가능한 캐시 판정에 들어가지 않는다.
- 읽기에 실패하면 마지막 잔액과 그 읽은 시각은 그대로 두고 상태만 바꾼다. 화면에는 `$12.34 (이전 값, 로그인 필요)`처럼 표시한다.
- ChatGPT 재로그인처럼 사용량 값을 이어받지 않는 저장에서도 잔액은 유지한다. 연결 해제(로그아웃)만 기존대로 스냅샷을 비우므로 잔액도 함께 사라진다.

## 안정성

- 새 명령 `open_api_credit_login`, `poll_api_credit_login`은 기존 세션의 소유 스레드와 워커 프로세스 경계를 그대로 통과한다.
- 로그에는 금액을 남기지 않는다. 페이지 구조가 달라 읽지 못하면 `api credit page not parsed` 줄에 숫자를 `#`로 가린 경로와 라벨 줄부터 세 줄만 남기고, 전자 우편 형태는 가린다. 플랫폼이 아닌 호스트(회사 통합 인증 등)는 `host=other`로만 적는다.
- 프로필 카드 메뉴 항목은 Codex 프로필이면서 조회·로그인·연결 해제 작업과 ChatGPT 로그인 확인 대기가 없고 프로필 잠금이 없을 때만 켜진다.

## 검증과 롤백

- 자동 테스트: 파서(라벨·금액·버튼 줄·로그인·챌린지·미렌더), 드라이버(별도 탭, 주기, 시간 예산, 실패 격리, 로그인 창 열기·확인·창 닫힘·프로필 잠금), 세션·프로세스·워커 명령 전달, 모니터(병합, 저장 복원, 로그인 흐름, 취소·로그아웃 경쟁), 프로필 관리자 위임, UI 행·메뉴, 오버레이 툴팁과 레이아웃 불변을 확인한다.
- 실제 Chrome 통합 테스트는 합성 결제 페이지 7종(제목 아래 금액, 버튼 사이 금액, 한 줄 flex, 인라인 span, 숨김·템플릿 중복, 미렌더, 로그인 이동)으로 프로브 스크립트와 파서를 함께 확인한다.
- 한계: 실제 계정의 인증된 결제 페이지는 사용자가 로그인해야 확인할 수 있다. 페이지 구조가 합성 페이지와 다르면 위 진단 줄로 원인을 좁힌다.
- 롤백: v0.36.9 실행 파일로 돌려도 상태 파일의 새 키는 무시된다. 이전 버전이 상태 파일을 다시 저장하면 새 키는 사라지고 다음 읽기에서 복구된다.
