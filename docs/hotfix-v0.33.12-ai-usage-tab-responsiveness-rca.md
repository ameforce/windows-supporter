# AI 사용량 탭 응답성·표시 hotfix

## 의도와 변경 분류

- 의도한 계약: AI 사용량 설정 탭은 프로필 수와 관계없이 멈춤 없이 열리고 스크롤·창 크기 조절에 바로 반응한다. 설정 영역은 한 카드 표면으로 보이고, Codex 조회 주소는 고정 상수(`CURRENT_CODEX_USAGE_URL`)다.
- 현재 동작: 프로필 10개에서 탭을 처음 열 때 약 1.4~2.0초, 다시 열 때 약 0.3~0.6초, 창 폭을 한 번 바꿀 때 약 0.6~0.9초 동안 화면이 멈춘다. 배치 우선순위 라디오 버튼은 테마 기본 회색 배경을 칠해 흰 카드 위에 떠 보인다. Codex 조회 URL 입력칸은 값을 바꿔도 조회 주소가 고정 주소로 정규화되어 효과가 없다.
- 차이: 응답성 계약과 카드 표면 표시가 지켜지지 않고, 조작해도 효과 없는 입력이 노출된다.
- 판정: 새 기능 없이 기존 화면의 성능 결함과 표시를 복구하므로 `hotfix/v0.33.12`로 분류한다.

## 근본 원인

측정 결과 탭을 열고 창 크기를 바꾸는 비용은 네이티브 위젯 수에 거의 비례했다. 이 환경에서 Tk 네이티브 창 하나는 첫 표시에 약 3ms, 창 폭 변경마다 약 2ms가 든다. 같은 글자를 캔버스 한 장에 그리면 10~20배 빠르다.

- 프로필 카드 하나가 네이티브 창 약 47개(Codex 기준)로 이루어졌다. 그중 지표 표가 지표마다 이름·값 Label 두 개씩 25개, 상태·경로 줄이 Label 5개였다. 프로필 10개에서 탭 전체는 439개였다.
- 카드·헤더·버튼 줄의 `<Configure>` 처리기는 값이 같아도 `wraplength`를 다시 설정하고 버튼을 다시 `pack`했다. 이 때문에 배치가 다시 예약되어 창 폭을 20단계 바꾸는 동안 처리기가 1,000번 넘게 호출되었다.

1초 주기의 상태 갱신은 틱당 약 3ms로 원인이 아니었다.

## 수정

- 카드의 상태 줄, 지표 표, 경로 줄을 캔버스 하나(`ProfileDetailCanvas`)의 텍스트 항목으로 그린다. 표시 여부 계약(`grid()`/`grid_remove()`), 넓은 폭의 2열 배치, 좁은 폭의 1열 배치, 이름 열 폭 예약, 설정 파일 줄 클릭, 기존 Label과 같은 간격을 유지한다.
- 줄바꿈 폭은 값이 바뀔 때만 적용하고, 버튼 줄은 배치 결과가 바뀔 때만 다시 배치한다.
- 라디오 버튼은 `ttk` 모양을 유지하고, 전용 스타일로 배경만 카드 색으로 칠한다.
- Codex 조회 URL 입력칸을 없애고 저장 내용에서도 `usage_url`을 보내지 않는다. 관리자는 고정 주소를 계속 사용한다.

## 결과

같은 기기에서 변경 전후를 번갈아 3회 측정한 중앙값이다(1040×700 창, 합성 프로필).

| 조건 | 네이티브 위젯 | 탭 첫 열기 | 탭 다시 열기 | 창 폭 변경 1회 |
|---|---|---|---|---|
| 프로필 10개 | 439 → 227 | 1,693ms → 869ms | 478ms → 167ms | 870ms → 380ms |
| 프로필 4개 | 205 → 119 | 1,463ms → 705ms | 304ms → 161ms | 522ms → 470ms |

남은 비용의 대부분은 버튼·체크박스·선택 상자 같은 조작 위젯의 Tk 네이티브 호출이다.

## 검증 범위

캔버스 지표 표의 2열·1열 정렬, 숨긴 행의 높이 반환과 열 고정, 값 변경과 줄바꿈, 요구 폭 상한, 상태·경로 줄의 위치와 클릭 연결, 카드 상세 영역의 네이티브 창 1개를 검증한다. 줄바꿈 폭과 버튼 줄의 중복 배치 방지, 라디오 스타일, URL 입력 제거와 저장 내용을 검증한다. 합성 네이티브 화면 12개 시나리오에서 레이아웃 안정성과 글자 넘침이 없는지도 확인한다.
