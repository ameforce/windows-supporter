# v0.8.4 PR 리뷰 게이트 비례화 RCA

## 변경 분류 기록

- 의도한 계약: exact base/head 이중 리뷰로 병합을 보호하되 실제 결함 위험이 있는 P0/P1/P2는 차단하고, 국소적·가역적·탐지 가능한 P3는 근거 있는 처분과 후속 추적으로 관리한다. 미해결 review thread는 항상 0이어야 한다.
- 현재 동작: AGENTS.md와 PR template은 P0/P1/P2/P3 모두 0이어야 병합할 수 있으며 P3의 처분·후속 책임·stale 처리 요건은 없다.
- 차이: 저위험 P3도 P2와 동일하게 무기한 병합 차단이 되어, 해결·기각·후속화 여부와 무관하게 exact-head 재검토 지연을 만든다. 반대로 P3를 비차단으로 바꾸려면 높은 위험을 P3로 낮추지 못하는 경계가 필요하다.
- 판정: 사용자 기능이나 제품 정책의 신규 도입이 아니라 리뷰 절차의 불완전한 위험 분류를 교정하는 v0.8.4 hotfix 운영정책 변경이다. 기존 제품 계약과 외부 CLI·공개 설정 API는 바꾸지 않는다.

## 적용 정책

- P0/P1/P2 중 하나라도 존재하면 병합을 차단한다. 병합 조건은 각각 0이다.
- P3는 병합 비차단이지만 finding ID, exact base/head, 처분, 근거, 검증, 책임자를 남기고 unresolved thread를 해소해야 한다.
- P3 처분은 수정, 기각, 위험수용, 후속 이슈 중 하나다. 기각에는 반증, 위험수용에는 **merge 시점에도 유효한 미래 만료일**, 후속 이슈에는 URL·owner·milestone·완료 조건이 필요하다. 만료된 위험수용은 stale·미완료로 처리해 새 처분 또는 P2 재분류가 필요하다.
- 데이터·설정 무결성, 보안·개인정보·인증, 공개 호환성, 삭제·업데이트·릴리스 무결성, 전역 상태 침묵 오류는 P3로 낮출 수 없다. 애매하면 P2이며 reviewer 불일치는 상위 등급을 사용한다.
- push 또는 base/head 이동은 두 리뷰, P3 처분, validation을 모두 stale로 만든다.

## 전환과 검증

- 이 정책 PR과 이미 열린 PR은 기존 `P0/P1/P2/P3 = 0` gate를 소급 적용한다. 이 PR의 merge commit 이후 새로 만드는 PR부터 P2 차단/P3 처분 정책을 적용한다.
- PR #24~#28은 backtest로 P3-only 라운드, P3에서 P1/P2로 승격된 사례, 지연 시간을 기록한다. 이 수치는 병합 근거가 아니라 정책 효과 측정용이다.
- 이후 새 PR 5개 또는 release 1회 동안 시범 적용한다. 지연된 P3의 P1/P2 승격, 재발, 기한 초과가 발생하면 all-zero gate 복귀를 재검토한다.
