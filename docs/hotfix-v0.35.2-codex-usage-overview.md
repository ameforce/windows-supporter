# Codex 프로필 OLD 표시 원인과 사용량 수집 복구

## 변경 분류

- 의도한 계약: 로그인한 각 프로필의 현재 한도, 크레딧과 초기화 시각을 주기적으로 갱신한다.
- 현재 동작: 2026-10-04 설치된 v0.35.1의 7개 Codex 프로필 모두 오전 10:39~10:51 이후 저장된 사용량이 갱신되지 않았다. 브라우저 탐색과 추출 실행은 성공하지만 수집기는 `parse_failed`를 반복했다.
- 차이: 기존 수집 주소가 공급자의 새 과거 사용 내역 화면으로 이동하고, 현재 한도가 있는 새 주소는 앱의 허용 대상에서 빠져 있었다.
- 판정: 기존 수집 계약의 호환성 결함 복구이므로 `hotfix/v0.35.2`다.

## 직접 확인한 원인

기존 `https://chatgpt.com/codex/cloud/settings/analytics#usage`를 실제 브라우저에서 열면 `https://chatgpt.com/settings/usage?tab=analytics#usage`로 이동했다. 이 화면에는 과거 기간과 채팅별 사용 내역이 표시된다. `개요`를 선택하면 `https://chatgpt.com/settings/usage?tab=overview`로 이동하며 현재 주간 한도와 크레딧이 표시됐다.

기존 주소 정규화는 저장된 설정을 계속 이전 analytics 주소로 보냈다. 수집기와 브라우저 드라이버가 별도로 관리하던 주소 판정에도 새 경로가 없었다. 따라서 재시도와 브라우저 재생성으로 같은 실패가 반복됐고 마지막 성공 값이 OLD로 남았다. OLD는 이 갱신 실패를 반영하는 정상적인 오래된 데이터 표시다.

새 개요 화면은 크레딧을 `62,462크레딧 남음`처럼 값 앞뒤 순서가 바뀐 형태로 표시한다. 초기화 시각은 상대 시간 옆의 `title`에 `2026년 10월 10일 토요일 오전 7시 40분 4초 GMT+9` 같은 정확한 시각을 담는다. 주소만 바꾸면 이 두 필드가 누락될 수 있었다.

## 수정

- 저장된 이전 주소와 새 analytics 주소를 현재 한도가 있는 overview 주소로 자동 이행한다.
- 수집기, 로그인 복귀 주소와 브라우저 드라이버가 공통 주소 계약을 사용한다. 탐색 대상 이행과 실제 도착 페이지 검증을 구분하므로 analytics 화면의 과거 수치를 현재 값으로 채택하지 않는다.
- 허용 호스트는 HTTPS의 정확한 `chatgpt.com`이며 다른 호스트와 로컬 시험 주소는 이행하지 않는다. 로그인 복귀 주소의 내부 쿼리 문자열은 하나의 `next` 값으로 인코딩한다.
- 새 크레딧 표기와 한국어 날짜의 명시적 GMT 오프셋을 읽는다. 기기의 시간대를 초기화 시각으로 추정하지 않는다.
- 기존 계정 일치 확인, 없는 5시간 한도의 생성 방지와 마지막 성공 데이터 보존은 유지한다.

## 검증 범위

변경 파일은 공통 주소 모듈, Codex 수집기와 브라우저 드라이버다. 직접 소비자인 다중 프로필 설정, 로그인 복귀, 추출, 초기화 판정에 해당하는 단위 시험과 실제 Chrome의 화면 없는 DOM 시험을 선택했다. 새 화면에서 식별 정보와 무관한 카드 구조를 재구성한 fixture로 한도, 크레딧, 정확한 초기화 시각, 로딩 중 과거 수치 오인 방지를 검증한다. 수정 전 새 회귀 시험의 실패를 확인했다.

전체 시험과 무관한 네이티브 화면 시험은 실행하지 않는다. 설치 배포 후에는 영구 실행 파일의 readiness, heartbeat와 실제 7개 프로필의 수집 시각 전진을 별도로 확인한다. 최종 버전, 커밋, 빌드와 배포 결과는 릴리스 증거에 기록한다.
