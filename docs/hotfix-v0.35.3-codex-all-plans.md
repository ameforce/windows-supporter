# Codex 전체 프로필의 사용량 갱신 복구

기존 수집 계약의 호환성 결함 복구로 `hotfix/v0.35.3`을 사용한다. 기존 주소가 과거 사용량 분석 화면으로 이동한 문제와 새 크레딧, 초기화 시각 표기는 [초기 RCA](hotfix-v0.35.2-codex-usage-overview.md)에 기록했다.

## 실제 프로필 검증에서 추가 확인한 원인

`v0.35.2` 후보의 실행 파일과 재시작은 정상이며 6개 프로필은 반복 갱신됐다. 그러나 120초 관찰에서 월간 한도를 사용하는 1개 프로필만 갱신되지 않아 공개 배포를 중단했다. 설치된 실행 파일을 잠시 중지하고 동일한 앱 수집기로 해당 프로필을 조회한 다음 배포 도우미로 같은 실행 파일의 재시작을 검증했다.

실제 응답은 정상 개요 주소였으며 로그인 계정도 기존 계정과 일치했다. 화면은 `월 사용 한도`, `0% 남음`을 표시했지만 파서는 `월간 사용 한도`만 알고 있어 한도를 버렸다. 이는 정상적인 소진 상태를 수집 실패로 오인한 결함이다.

같은 응답의 표시 본문에는 없던 과거 한도 영역이 DOM 추출 블록에 포함됐다. 새 설정 화면은 비활성 분석 탭도 DOM에 유지한다. 기존 추출기는 숨겨진 요소의 `textContent`를 대체값으로 읽어 현재 화면 밖의 과거 수치를 채택할 수 있었다. 실제 Chrome 회귀 시험에서 숨겨진 과거 5시간 한도를 새로 만들고, 현재 한도가 로딩 중일 때 숨겨진 주간 수치를 채택하는 실패를 각각 재현했다.

## 수정과 검증

- 기존 주소 이행, 공통 주소 판정, 크레딧과 정확한 초기화 시각 수정 커밋을 재사용한다.
- 현재 공급자의 `월 사용 한도`를 월간 한도 이름으로 인식하고 `0%`도 정상 수집 값으로 유지한다.
- 현재 보이는 요소의 렌더링된 텍스트만 읽는다. 숨겨진 요소의 날짜 속성도 제외하며, 빈 렌더링 텍스트를 숨겨진 `textContent`로 보완하지 않는다.
- 월간 소진 상태, 숨겨진 다른 한도, 같은 한도의 숨겨진 과거 수치에 대한 회귀 시험 3개가 수정 전에 실패하는 것을 확인했다.
- 동일한 7개 실제 프로필에서 새 실행 파일 배포 이후 수집 시각이 두 번 이상 전진하고, 앱 heartbeat가 120초 유지되는지를 공개 전 필수 확인으로 둔다.

## 버전과 실패 기록 보존

`v0.35.2` 태그와 배포, 시험, 실패 관찰 기록은 덮어쓰지 않는다. 해당 후보는 GitHub Release와 공개 main/tag/develop으로 배포하지 않았다. 공개된 `main` v0.35.1에서 새 hotfix lane을 만들고 이미 검토한 수정 커밋을 포함했다. 정식 공개 대상은 전체 프로필 검증을 통과한 `v0.35.3`이다. 이전 후보의 ref와 원래 남아 있던 다른 버전의 정리 의무는 이번 작업에서 임의로 삭제하지 않는다.
