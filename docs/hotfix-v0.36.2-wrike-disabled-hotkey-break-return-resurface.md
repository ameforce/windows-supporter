# Wrike 비활성화 단축키 차단과 휴게 복귀 질문 재표시

## 분류와 계약

- 의도
  1. Wrike를 끄면 근무시간 창은 자동으로도 직접 열어서도 나타나지 않아야 한다. 대시보드의 `Wrike` 카드는 "비활성화"라고만 표시하고, 설정 탭도 같은 스위치를 쓴다.
  2. 수동 휴게 중 설정한 무입력 시간 이상 입력이 없다가 입력이 생기면, 휴게 종료 여부를 묻는 화면이 사용자에게 도달해야 한다(v0.36.0, 2026-10-14 요청).
- 기존 동작
  1. v0.35.11 문서는 "사용자가 직접 여는 근무시간 창은 사용할 수 있다"고 정했고 시험이 이를 고정했다. 그래서 Wrike를 꺼도 `Ctrl+Alt+W`가 근무시간 창을 열고 Wrike 조회까지 시작했다. 화면 문구는 기능 전체가 꺼진다고 읽히는데 실제로는 자동 알림만 꺼졌다.
  2. 복귀 질문의 자동 표시 시도는 입력 한 번에 한 번뿐이었다. 자동으로 뜬 패널은 `툴팁 표시 시간`(기본 6초) 뒤 스스로 닫히므로, 그 한 번을 놓치면 질문이 남아 있어도 이후 입력으로는 다시 뜨지 않았고 `Ctrl+Alt+W`로 열어야만 보였다. 이 흐름은 어느 단계도 로그로 남기지 않아 놓친 원인을 사후에 알 수 없었다.
- 차이: 두 경우 모두 의도한 사용자 경험에 닿지 못한다. 1은 v0.35.11 계약 자체가 어긋났고, 2는 질문을 사용자에게 전달하는 구현이 한 번의 표시에 의존했다.
- 판정: 새 사용자 기능이 아니라 기존 의도(Wrike 비활성화, 휴게 종료를 묻는 화면)의 계약 오류와 불완전 구현을 복구하므로 `hotfix/v0.36.2` 차선에서 고친다. v0.35.11의 수동 열기 허용은 사용자가 확정했다는 기록을 찾지 못한 해석이었고, 사용자가 이번 요청에서 의도를 명시했다.

## 확인한 원인

1. `Wrike.show_weekly_timelog_summary`는 `monitor_enabled`를 확인하지 않았다. 새로고침 함수도 같은 값을 보지 않아, 비활성화 상태의 수동 열기가 Wrike 조회를 시작했다.
2. 실제 `Tk` 패널을 임시 설정에서 격리 재현했다. 40분 휴게 뒤 첫 입력에서 0.1~0.2초에 카드가 표시되고 설정한 표시 시간 뒤 닫혔다. 이후 입력 4회에도 표시 호출은 1회 그대로였고 `Ctrl+Alt+W`에서만 다시 보였다.
3. 실제 PC에서 첫 표시가 보이지 않은 이유는 확정하지 못했다. 당시 휴게 종료 기록은 질문이 만들어졌음을 시사하지만, 잠금과 화면 상태를 알 수 있는 기록이 없다. 그래서 원인과 무관하게 질문이 사용자에게 도달하도록 재표시를 넣고, 다음에 안 보이면 원인을 바로 확인할 수 있도록 단계를 로그로 남긴다.

## 수정 범위

- Wrike가 꺼져 있으면 근무시간 창을 여는 공용 함수(`show_weekly_timelog_summary`)가 창을 열지 않고 Wrike를 조회하지 않는다. `Ctrl+Alt+W`와 트레이 메뉴가 이 함수를 쓴다. 대신 "Wrike가 꺼져 있어 근무시간 창을 열지 않습니다. 대시보드나 Wrike 설정 탭에서 Wrike를 켜 주세요." 안내를 직접 요청에 대한 응답으로 표시한다. 다시 켜면 이전처럼 열린다.
- 대기 중인 휴게 복귀 질문은 이후 입력에서 `BREAK_RETURN_RESURFACE_SECONDS`(120초) 간격으로 다시 표시한다.
  - 패널이 화면에 떠 있는 동안의 입력과 `Ctrl+Alt+W`로 직접 연 것은 본 것으로 계산한다. 마지막으로 본 시각부터 간격을 세므로, 보고 닫은 직후에는 다시 띄우지 않는다.
  - 답하거나(`종료`, `시간 수정`, `계속 휴게`) 휴게가 끝나거나 자동 알림이 꺼지면 멈춘다.
  - 휴게가 끝났는지는 마지막으로 본 뒤 간격이 지난 첫 입력에서 확인한다. 패널이 화면에 떠 있고 입력이 끊기지 않는 동안에는 이 확인이 미뤄져 끝난 휴게의 질문이 메모리에 남을 수 있다. 카드는 휴게가 진행 중일 때만 만들어지므로 화면에는 나타나지 않고, 입력이 간격 이상 끊기거나 패널이 닫힌 뒤 간격이 지나면 지운다.
  - 잠금 해제로 다시 표시한 시각도 같은 간격 계산에 쓴다.
  - 표시에 실패해도 다음 시도는 같은 간격을 기다린다. 시스템 시계를 되돌리면 다음 입력에서 한 번 표시하고 그 시각부터 간격을 다시 센다.
- 질문을 띄운 같은 입력에서 온 직접 열기 요청은 패널을 닫지 않는다. `Ctrl+Alt+W`를 누르면 입력 감시자(0.5초 주기)가 키 입력을 먼저 처리해 패널을 띄운 뒤 핫키 작업이 토글로 곧바로 닫을 수 있었다. 질문을 띄운 지 `BREAK_RETURN_HOTKEY_GRACE_SECONDS`(1.5초) 안에 오는 직접 열기는 보이는 패널을 그대로 두고 본 것으로 계산하며, 조회는 그대로 시작한다. 그 뒤의 요청은 기존 토글대로 동작한다. 트레이 메뉴는 메뉴로 가는 마우스 이동이 패널을 먼저 띄울 수 있고, 이어지는 클릭은 토글 동작대로 닫는다.
- 단계 로그를 `wrike.log`에 남긴다. 입력마다 남기지 않는다.
  - `break return:` 접두 줄: 긴 부재 감지(입력 시각, 부재 시작, 휴게 시작), 무시한 이유, 질문 기록과 표시 결과(성공 여부, 실패 이유, 패널의 표시와 위치 상태), 재표시, 이미 화면에 있어 건너뛴 결정(간격이 지난 뒤 첫 입력에서 한 번), 잠금 해제 처리, 답변과 질문 삭제 이유.
  - 입력 감시자 생성 또는 시작 실패(시작 뒤 폴링이 멈춰 있는 경우 포함)와, 수명주기가 바뀐 뒤 버려진 입력 콜백(세대마다 한 번).
- `WorktimeQuickPanel.describe_state()`를 추가했다. 로그용 읽기 전용 조회이며 화면과 시간 제한에 영향이 없다.
- 설정 탭과 대시보드의 문구는 바꾸지 않는다. 설정 탭의 "Wrike 자동 알림 활성화"는 이제 직접 여는 창도 함께 막으므로, 안내 문구에 대시보드와 설정 탭을 함께 적었다. 스위치 이름을 "Wrike 활성화"로 맞출지는 별도로 정한다.
- 알려진 상호작용: 휴게 중에 Wrike를 껐다 켜거나 앱을 다시 시작하면 입력 감시 기준 시각이 휴게 시작으로 잡혀, 자리에 있던 사용자에게도 복귀 질문이 생길 수 있다(v0.36.0 계약). 이 질문도 이제 답할 때까지 이후 입력에서 다시 표시된다. 기준 시각 처리는 이번 범위 밖이며 `계속 휴게`로 답하면 멈춘다.
- v0.35.11과 v0.36.0 문서의 해당 문장과 `scripts/qa_wrike_disabled_ui.py`의 기대값을 같은 변경에서 정정한다.

## 검증 범위

- 직접 영향 단위시험: `test_wrike_break_return_prompt`, `test_wrike_disabled_lifecycle`, `test_wrike_worktime_panel`, `test_wrike_break_edit_regressions`, `test_wrike_realtime_progress`, `test_monitor_hotkey`, `test_monitor_hotkeys`.
- 새 시험 34개를 수정 전 소스(v0.36.1)에 덮어 실행해 대조했다. 28개는 수정 전 소스에서 실패하고 수정 후 통과한다. 나머지 6개(답한 질문은 다시 뜨지 않음, 간격 안의 입력은 로그를 남기지 않음, 직접 열기가 먼저일 때 패널이 하나만 남음, 간격 안에서도 숨은 패널은 직접 열기로 열림, 감시자가 동작 중이면 시작 실패를 남기지 않음, 입력이 이어져도 끝난 휴게의 카드는 나타나지 않음)는 회귀 방지용이라 양쪽에서 통과한다.
- 변이 시험으로, 입력마다 로그가 늘어나는 변경, 시계를 되돌린 때 재표시가 막히는 변경, 화면에 있는 동안의 간격 갱신을 빼는 변경, 화면에 떠 있으면 휴게 확인을 건너뛰는 변경, 직접 열기 유지의 점검과 표식과 창 길이와 표시 조건을 빼거나 바꾸는 변경, 감시자 비동작과 답변 종료와 삭제 이유 로그를 빼는 변경, `describe_state`가 타이머를 다시 거는 변경을 새 시험이 실제로 잡는지 확인했다.
- 변경된 상태의 네이티브 확인: `scripts/qa_wrike_disabled_ui.py`(임시 설정, 네트워크와 자격 증명 차단). 비활성화 중 수동 열기 차단과 재활성화 뒤 복구를 포함한다.
- 전체 시험과 앱 전체 실행 시험은 실행하지 않는다. 변경이 `Wrike`와 근무시간 패널에 한정되고 직접 소비 모듈을 모두 실행했다. 배포 산출물은 태그에서 한 번 만든다.
