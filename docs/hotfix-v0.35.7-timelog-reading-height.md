# v0.35.7 타임로그 최소 읽기 높이 복구

## 변경 분류

- 의도한 계약: 선택 날짜의 타임로그를 티켓별로 읽을 수 있고, 출근 확인이나 초과근무 상태가 추가되어도 기본 읽기 영역과 하단 작업 버튼을 사용할 수 있어야 한다.
- 현재 동작: 전체 패널의 570px 상한을 맞추기 위해 타임로그만 8행에서 최소 3행으로 줄인다. 추가 카드가 많으면 하단 작업 버튼도 잘린다.
- 차이: 보조 상태 표시가 핵심 읽기 영역과 버튼 접근성을 훼손한다. 화면에 남는 공간도 고정 상한 때문에 활용하지 못한다.
- 판정: 기존 UI 계약의 불완전 구현을 복구하는 hotfix. 새로운 업무 기능이나 저장 형식을 추가하지 않는다.

## 구현 및 검증 범위

화면 코드 `src/apps/wrike_worktime_panel.py`의 높이 배분과 직접 영향받는 패널 테스트만 변경한다. `scripts/qa_wrike_reading_height.py`는 실제 Tk 창에 합성 데이터를 넣고 네 가지 화면 조건에서 기본, 출근 확인, 초과근무 제안, 초과근무 진행, 복합 상태를 비교한다. 사용자의 Wrike 또는 Flex 기록을 변경하지 않는다.

수용 기준:

- 데이터가 있는 타임로그의 기본 표시 영역을 확대한다.
- 같은 화면 크기와 배율에서는 추가 UI가 생겨도 타임로그의 실제 픽셀 높이를 유지한다.
- 검증 화면 조건에서 본문 글꼴 기준 최소 8행을 표시하고, 하단 작업 버튼이 잘리지 않는다.
- 작은 화면에서는 보조 영역을 조정하며 그 안의 날짜와 작업 버튼에 접근할 수 있다.
- 선택 날짜, 타임로그 스크롤 위치, 시간 편집과 비활성화 표시 동작을 보존한다.

화면 조건은 1280x960, 800x640, 608x535의 100% 배율과 800x640의 150% 배율이다. 실제 Tk 위젯과 Windows `PrintWindow`를 사용하고, 작업 영역과 Tk 글꼴 배율만 주입한다. 물리 모니터 설정을 변경한 시험은 아니다.

## 수정 전 재현

기준 소스는 `v0.35.6`, `41bec96bedfa02b122281513f238c72f7282940d`이다.

- 100% 배율에서 기본 타임로그 높이는 114px, 복합 상태는 51px였다.
- 608x535에서는 출근 확인 하나만 추가해도 114px에서 51px로 줄었다.
- 복합 상태에서는 하단 버튼이 잘렸고, 150% 배율에서는 기본 상태부터 하단 표시 공간이 부족했다.

수정 전후 화면과 측정값은 저장소 밖의 `C:\Users\enmso\.codex\artifacts\windows-supporter\v0.35.7`에 보관한다. 전체 테스트 대신 변경 동작에 직접 관련된 단위 테스트와 이 화면 검증을 수행한다.

## 수정 결과

- 데이터가 있는 타임로그는 기본 12행을 제공한다. 고정 570px 상한을 없애 실제 작업 영역에 맞춰 창을 확장한다.
- 헤더, 타임로그, 하단 버튼을 보조 영역과 분리한다. 출근 확인, 초과근무, Flex 등록 대기, 오늘 요약과 날짜 목록은 공간이 부족할 때 별도로 스크롤한다.
- 같은 작업 영역에서는 추가 상태 수가 타임로그 높이를 바꾸지 않는다. 12행과 고정 영역 자체가 들어가지 않는 작은 화면에서만 최소 8행까지 조정한다. 그 최소 영역조차 들어가지 않는 화면에는 물리적 한계가 있다.
- 시간 편집란은 보조 영역 맨 위에 표시해 접근할 수 있도록 한다. 타임로그에서 읽던 위치는 보존한다.

실제 Tk 비교 검증 20개 상태에서 타임로그 높이 유지, 최소 8행, 하단 버튼 노출, 작업 영역 안 배치를 모두 통과했다. 100% 배율의 세 화면 조건에서는 모든 상태가 166px, 12행을 유지했고, 150% 배율에서는 모든 상태가 262px, 12행을 유지했다.

단위 테스트는 `tests.unit.test_wrike_worktime_panel`과 `tests.unit.test_qa_wrike_timelog_details.IndependentDatePanelAcceptance`의 62개, 이후 보강한 native 경계 테스트 1개가 통과했다. UI가 바뀌는 범위만 검증했으며 전체 테스트나 무관한 E2E는 실행하지 않았다.

독립 검토에서 보조 영역의 숨은 버튼에 Tab 포커스만 이동하는 결함을 발견해, 하위 위젯의 `FocusIn`에서 필요한 만큼 자동 스크롤하도록 보완했다. 800x640, 150% 배율에서 Tab과 Shift+Tab으로 Flex 수정과 완료 버튼, 시간 입력란이 노출되는 실제 Tk 시험을 추가했다. 이 시험, 읽기 높이 시험, 비활성화 표시 시험의 3개가 통과했다.

후속 검토에서 조상 Frame의 포커스 이벤트와 배치 중 좌표 계산이 편집란 상단을 가리는 회귀를 발견했다. 실제 포커스 위젯만 처리하고 `after_idle`에서 현재 포커스와 배치를 다시 확인하도록 수정했다. 높이 시험 단독과 양방향 Tab 시험의 결합 실행이 통과했다. 최종 화면 비교 도구도 네 가지 화면 조건에서 보조 영역 끝까지 스크롤, 편집란 전체 노출, 상세 높이 불변을 추가 확인했다. 최종 저장 화면은 기본 상태 20개와 상호작용 화면 8개, 총 28개다.

Pro 검토는 브라우저 초기화 호출의 30초 시간 초과로 자료 전송 전에 생략했다. 로컬 독립 검토와 실제 화면 검증으로 작업을 진행한다.
