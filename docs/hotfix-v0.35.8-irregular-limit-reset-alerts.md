# 비정기 사용 한도 초기화 알림 복구

## 의도와 변경 분류

- 의도한 계약: 프로필의 사용 한도가 초기화되면 초기화 툴팁과 효과음을 한 번 알린다.
- 현재 동작: 미래의 초기화 예정 시각이 남아 있으면 잔여량이 완전히 회복돼도 초기화로 감지하지 않는다.
- 차이: 예정 시각보다 먼저 일어난 공급자의 초기화를 놓친다.
- 판정: 기존 초기화 알림 계약의 감지 누락을 복구하는 `hotfix/v0.35.8`이다.

## 변경

- Codex와 Claude가 같은 관측 함수를 사용한다. 예정 시각이 남아 있거나 변경됐거나 사라졌어도, 실제로 측정한 잔여량이 15분 안에 5%p 이상 증가해 99% 이상이 되면 비정기 초기화 후보로 잡는다.
- 다음 정상 수집에서도 99% 이상인 것을 확인한 뒤 알린다. 같은 수집 결과의 재처리나 과거 관측은 확인 횟수에 포함하지 않는다. 확인 간격이 15분을 넘거나 값이 내려가거나 파싱에 실패하면 후보를 취소한다.
- 알린 상태와 확인 중인 후보를 계정별 상태 파일의 `limit_reset_state`에 저장한다. 재시작 후에도 이어서 판정한다. 연결을 해제하면 해당 계정의 판정 상태를 지운다.
- 이전 버전 파일에 새 필드가 없으면 마지막 저장 관측으로 초기 상태를 채운다. 업그레이드 직후에도 수집 간격 조건을 만족하는 회복을 놓치지 않는다.
- 한 번 알린 뒤에는 잔여량 95% 이하가 두 번 연속 정상 관측돼야 다음 비정기 초기화를 감지한다. 한 차례 낮은 값이 섞였다가 다시 100%가 되는 현상은 같은 초기화로 처리한다.
- 예정 시각이 실제로 지난 뒤 새 시각으로 넘어가는 기존 초기화는 즉시 알린다. 부재 중 효과음 설정과 사용자 복귀 후 툴팁 표시 정책은 유지한다.
- Claude도 관측 상태를 저장한 다음 알림을 제출한다. Codex의 감지, 상태 갱신과 저장은 같은 잠금 안에서 처리한다.

## 검증 범위와 한계

직접 영향 범위는 공용 감지 함수, Codex 스냅샷 저장과 자동 수집, Claude 관측 저장과 복원이다. 관련 단위 시험으로 예정 시각 유지·변경·누락, 일시적인 수치 튐, 작은 회복, 긴 수집 공백, 파싱 실패, 역순 관측, 재수집, 재시작, 다음 소비 구간과 정상 예정 초기화를 확인한다. 툴팁과 효과음은 모의 호출로 횟수를 검증하고 후보 실행 파일을 빌드한다. 화면 구성과 출력 구현은 바꾸지 않으므로 실제 창을 띄우는 시험과 전체 suite는 추가하지 않는다.

공급자가 명시적인 초기화 이벤트 ID를 주지 않으므로 동일한 수치와 시각을 내는 지속적인 잘못된 응답과 실제 초기화를 완벽히 구분할 수는 없다. 작은 회복이나 수집 공백 뒤의 회복은 오탐 방지를 위해 추론하지 않는다. 비정기 초기화 알림은 정상 수집 한 회만큼 늦어지며, 기존 부재 중 표시 정책에 따라 툴팁이 더 늦게 나타날 수 있다.
