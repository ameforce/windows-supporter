# 크레딧 전용 사용량 화면의 수집 복구

사용량 화면이 현재 제공하는 지표를 수집하고, 없어진 지표는 과거 값으로 채우지 않는 것이 의도한 계약이다. enmsoftware 프로필은 인증된 사용량 화면에서 크레딧만 제공했지만 수집기는 한도 카드가 없으면 준비되지 않은 상태로 판단했다. 기존 계약의 누락을 복구하므로 `hotfix/v0.35.6`으로 분류한다.

## 확인한 원인

- 실제 계정은 `/settings/usage?tab=overview`에서 `/?tab=overview#settings/Usage`로 이동했다. 사용량은 배경 `main` 바깥의 활성 설정 대화상자에 표시됐다.
- 기존 수집 범위는 배경 `main`을 읽었고, URL 판정은 이 설정 경로를 거부했으며, 준비 판정과 스냅샷 생성은 한도 지표를 요구했다. 세 조건이 정상적인 크레딧 전용 화면을 지원하지 못했다.
- 2026-10-05 12:51:40 이후 성공한 수집이 없어 과거 월간 100%와 초기화 시각이 남았다. `OLD`는 이 수집 실패를 표시한 결과다.
- 원래 프로필의 인증 쿠키를 복사한 격리 브라우저에서 사용자와 계정 인증 및 기존 계정 일치를 확인했다. 실제 활성 패널에는 62,462 크레딧만 있고 한도 카드는 없었다. 계정의 전체 정책이나 다른 계정의 동작으로 일반화하지 않는다.

## 수정 계약

- 정확한 ChatGPT 설정 사용량 URL과 보이는 활성 Usage 패널에서만 크레딧 전용 상태를 인정한다. 일반 overview에서 크레딧이 먼저 나타난 로딩 상태는 계속 거부한다.
- 패널의 로딩 표시가 없고 숫자 잔액이 있어야 하며, 수용 전 인증된 사용자와 계정 ID를 확인한다. 계정 불일치 거부와 0 크레딧 수용을 유지한다.
- 인증 조회 실패 시 완성된 화면 판정은 반환하되 데이터 수용은 거부한다. 준비 루프 안에서 느린 인증 조회를 반복하지 않는다.
- 현재 보고된 지표를 `remaining_credit`로 제한해 과거 월간, 주간, 5시간 한도와 초기화 시각을 제거한다. 이 경로에는 로컬 한도 보완을 적용하지 않는다.
- 준비 실패 로그는 경로 분류, 지표 수와 텍스트 존재 여부만 남긴다. 인증값이나 화면 원문을 기록하지 않는다.

## 검증

수정 전 재현 시험 15개 중 8개 실패와 1개 오류를 확인했고, 수정 후 같은 시험이 통과했다. URL, 전송 형식, 준비 판정, 인증, 스냅샷 갱신, 저장 후 재로드와 실제 Chromium DOM을 포함한 관련 시험 75개가 통과했다. 로딩 패널과 자식 로딩 표시도 직접 검증한다. 전체 시험 모음과 무관한 UI 시험은 실행하지 않는다.

수정된 소스의 격리 브라우저 수집은 2026-10-05 15:02:04에 성공했다. 기존 계정 일치를 확인한 뒤 크레딧 62,462를 수용하고 과거 월간 값과 초기화 시각을 제거했다. 독립 코드 검토에서 차단 결함은 없었다. Pro 검토는 기존 인증 challenge로 사용할 수 없어 건너뛰었다. 설치된 실행 파일의 지속 수집은 배포 후 별도로 확인한다.
