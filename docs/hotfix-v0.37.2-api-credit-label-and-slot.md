# v0.37.2 API 크레딧 실제 라벨 판독과 CR 옆 표시

## 판정

- 의도한 계약: v0.37.0과 v0.37.1의 요청은 OpenAI Platform 결제 개요의 API 크레딧 잔액을 읽어 작업표시줄의 Codex 사용량과 같이 띄우는 것이다.
- 현재 동작: 사용자가 로그인한 실제 결제 개요에서 잔액을 찾지 못해 `조회 불가`가 된다(로그 `api credit page not parsed reason=balance_not_found ... label_line=-1`). 읽더라도 ChatGPT 크레딧 `CR`이 있는 행에는 API 칸이 생기지 않는다.
- 차이: 실제 카드 제목이 `API credit balance`이고, 판독기는 `Credit balance`로 시작하는 줄만 라벨로 봤다. 또 v0.37.1은 한 행에 금액 칸을 하나로 제한해 빈 세 번째 칸이 있어도 API를 넣지 않았다.
- 판정: 의도한 표시의 결함이므로 hotfix다.

## 동작

- 주 라벨에 `API credit balance`, `API credits balance`, `API 크레딧 잔액`을 더했다. 라벨은 여전히 줄 맨 앞에 있어야 하므로 `Your API credit balance is low` 같은 문장은 라벨이 아니다. 금액 규칙(같은 줄, 바로 아래 줄, 버튼 줄 최대 2개 뒤)은 그대로다.
- 작업표시줄에서 API 잔액은 자기 칸 키(`api_credit`)를 가진다. `CR` 칸과 나란히 놓일 수 있고, 두 칸은 각자 열과 폭을 가진다. 두 칸 모두 막대 없이 이름표와 금액만 그리고, 좁으면 짧은 표기를 쓴다.
- 칸 순서는 5시간, 주간, 월간, `CR`, `API`다. 한 행에 그리는 칸은 여전히 3개이므로, 앞의 칸이 3개를 채우면 API 칸은 생기지 않고 잔액은 다른 칸의 툴팁에 남는다.
- v0.37.1 문서의 "`CR`이 이미 있으면 API 칸을 만들지 않는다"는 이 문서로 바뀐다.

## 검증

- 자동 테스트: 실제 결제 개요의 텍스트 순서로 `$140.00`을 읽는지, 한국어 라벨과 같은 줄 금액, 문장형 라벨 거부. 주간과 `CR`만 있는 행에 API 칸이 세 번째로 붙는지, `CR`과 API 열이 따로 잡히고 두 금액이 모두 잘리지 않는지.
