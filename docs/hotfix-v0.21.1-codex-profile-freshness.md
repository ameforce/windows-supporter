# Codex 표시명과 초기화 시각 갱신 복구

## 목적과 변경 분류

현재 계정의 실제 표시명과 현재 사용량 시간창을 표시하도록 기존 수집 계약을 복구한다.

- 의도한 계약: 사용량 비율이 같아도 새 수집 결과를 반영하고, 현재 로그인한 사용자의 ChatGPT 표시명을 자동으로 읽는다.
- 현재 동작: 로그인 이름을 사용자 지정 표시명보다 먼저 선택하며, 새 사용량에 초기화 시각이 없으면 과거 시각을 채워 넣는다.
- 차이: 프로필 메뉴를 직접 열어야 사용자 지정 이름이 보일 수 있고, 수동 사용량 재설정 뒤에도 과거 시간창의 카운트다운이 남을 수 있다.
- 판정: 새 기능 도입이 아닌 현재 노출된 수집·표시 오류 복구이므로 `hotfix/v0.21.1`로 분류한다.

## 확인한 사실과 원인

실행 중인 앱은 잔여량이 100%인 동안에도 약 30초 간격으로 페이지를 다시 읽고 수집 시각을 저장했다. 비율이 같으면 수집을 멈춘다는 가설은 이 기록과 코드 경로에서 반증됐다. 화면의 카운트다운도 별도의 1초 갱신 경로가 있다.

같은 로그인에서 `/api/auth/session`과 `/backend-api/me`는 로그인 이름을 반환했지만, ChatGPT의 프로필 화면과 `/backend-api/calpico/chatgpt/profile/<user.id>`는 다른 사용자 지정 표시명을 반환했다. 프로필 응답의 `user_id`는 세션의 `user.id`와 일치했다. 프로필 메뉴를 거친 뒤 화면의 이름이 바뀌는 현상도 관찰했다. 기존 수집기는 로그인 이름을 먼저 반환하므로, 사용자 지정 이름이 존재해도 그 경로를 사용하지 않았다. 대체 경로의 브라우저 저장소 탐색도 현재 사용자와 무관한 여러 사용자 키를 후보로 삼았다.

초기화 시각 병합은 별도 결함이다. 실제 수집 호출과 저장 경로를 연결한 재현에서, 이전 잔여량 98%와 초기화 시각 뒤에 새 잔여량 100%·초기화 시각 없음이 들어오면 과거 시각을 새 수집 시각과 함께 저장했다. 100%가 계속되는 경우에도 같은 문제가 재현됐다. 당시 실제 계정의 원본 응답 전체를 보존한 것은 아니므로, 이 재현만으로 당시 공급자가 반환한 시각까지 단정하지 않는다.

[OpenAI의 재설정 안내](https://help.openai.com/en/articles/20001498-how-banked-codex-resets-work)에 따르면 전체 재설정은 주간 초기화 날짜도 바꾼다. WS가 이전 날짜를 임의로 유지하거나 새 날짜를 추정해서는 안 된다.

## 수정된 계약

- 사용량 한도 블록이 준비된 수집에서 현재 세션 사용자에 해당하는 프로필을 새로 요청한다. 메뉴를 열거나 포커스를 바꾸지 않는다. 크레딧만 보이는 중간 화면의 재시도에서는 신원 조회를 반복하지 않는다.
- 프로필 응답의 사용자 ID가 현재 세션 사용자와 정확히 일치할 때만 사용자 지정 표시명을 채택한다.
- 확인된 사용자 지정 이름은 화면 메뉴 장식 제거 규칙을 적용하지 않고 보존한다. 예를 들어 `Alice Pro`와 `Profile`도 이름 그대로 저장하고 앱 재시작 뒤에 유지한다. 기존 저장 데이터는 검증 표시가 없는 경우 종전 정리 규칙을 따른다.
- 세션의 인증 값은 같은 출처의 프로필 조회에만 사용하고, 결과·로그·상태 파일로 반환하지 않는다. 조회는 시간 제한을 두고 리디렉션을 거부한다.
- 프로필 조회의 일시 실패는 사용량 수집을 막지 않으며 마지막으로 확인한 이름을 유지한다. 존재하지 않는 사용자 지정 프로필은 로그인 이름을 대체값으로 사용할 수 있다.
- 새로 읽은 지표 값에 초기화 시각이 없으면 과거 시간창의 시각을 가져오지 않는다. 지표 값 자체의 일시적인 파싱 실패와 기존 부분 결과의 보완 동작은 유지한다.
- 초기화 시각이 없는 상태 뒤에 같은 100%로 새 시각이 제공되면 즉시 저장한다.

## 검증 범위

브라우저 수집 스크립트는 실제 Playwright의 화면 없는 테스트에서 합성 세션·프로필 응답으로 검증한다. 두 계정 이름, 같은 비율에서 이름 재조회, 사용자 ID 불일치, 인증·서버 오류, 세션 정보 부재, 메뉴 클릭 부재와 인증 값 비노출을 확인한다.

독립 최종 검토의 추가 지적은 먼저 실패를 재현한 뒤 수정했다. 사용자 이름의 원문 보존은 실제 브라우저 결과에서 파싱·저장·재로드까지 확인한다. 중간 화면의 반복 조회는 실제 21회 준비 대기 경로에서 신원 요청이 발생하지 않고, 한도 화면이 준비된 다음 수집부터 다시 조회하는지 확인한다.

초기화 시각은 수집 호출 → 파싱 → 병합 → 저장 경로로 검증하며, 과거 시각 제거와 같은 100%에서 새 시각 반영, 값 파싱 실패 시 기존 보완 동작을 함께 확인한다. 기존 수집기 단위 테스트와 화면 구조 파싱 테스트도 실행한다. 전체 테스트와 무관한 화면 검증은 변경 범위에 포함하지 않는다.

실행 파일 배포와 실제 두 계정의 재수집 결과는 최종 배포 증거에 별도로 결합한다. 실패 시 이전 실행 파일로 되돌리는 기존 배포 절차를 사용한다.
