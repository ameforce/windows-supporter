# 작업표시줄 오버레이 컴팩트 fit 복구

## 분류와 의도

작업표시줄 AI 사용량 오버레이는 표시 가능한 공간 안에서 프로필명과
사용량 정보를 서로 밀어내지 않고 읽을 수 있어야 한다.

- 의도한 계약: 프로필명 영역은 현재 표시 프로필명의 실제 글꼴 폭과 끝 여백만 확보하고, 남은 폭은 사용량 지표에 사용한다.
- 현재 동작: 일반 폭에서도 프로필명 영역이 64px 이상, 오버레이 폭의 비율, 76px 상한을 우선해 짧은 이름 옆에 고정 여백이 남는다.
- 차이: 이름이 짧은 경우에도 지표 영역이 불필요하게 줄어들어 작은 작업표시줄 슬롯에서 정보가 빽빽해지고, 오버레이가 콘텐츠보다 넓게 보인다.
- 판정: 새 capability가 아닌 기존 표시 fit 계약의 불완전 구현 복구이므로 `hotfix/v0.23.3`으로 분류한다.

## 수정 계약

- 일반 폭에서는 실제 오버레이 폰트로 측정한 표시 프로필명 중 가장 긴 폭에 끝 여백만 더해 프로필명 열을 계산한다.
- 프로필명이 짧아진다고 다른 열의 정렬을 깨지 않는다. 공유 지표 열은 유지하고, 모든 행의 가장 긴 표시명만 공통 기준으로 사용한다.
- 실제 슬롯이 compact 구간이면 기존 지표 우선 fallback과 픽셀 기반 말줄임표를 유지해 지표가 프로필명 때문에 캔버스 밖으로 밀리지 않게 한다.
- 프로필명 폭이 줄어든 만큼 preferred overlay width 계산도 함께 줄어들어, 여유 공간을 불필요하게 예약하지 않는다.

## 검증

- `tests/unit/test_codex_usage_taskbar_overlay.py`
- 짧은 프로필명 열의 폭이 오버레이 폭과 무관하게 실제 최대 이름 폭에만 따라가는지 검증한다.
- 긴 프로필명은 정상 폭에서 전체 표시되고, compact 폭에서는 지표 우선 fit이 유지되는지 검증한다.
