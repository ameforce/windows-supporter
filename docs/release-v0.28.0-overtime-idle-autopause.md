# v0.28.0 초과근무 무입력 자동 일시정지 계약

## 변경 분류

- 의도한 계약: 초과근무 타이머는 사용자의 수동 시작·일시정지·종료로 실제
  근무시간을 측정한다.
- 현재 동작: 입력 유휴와 무관하게 수동 조작 전까지 계속 누적되며,
  일시정지·재개는 모두 수동이다.
- 차이: 마우스·키보드 입력이 일정 시간 없을 때 자동으로 일시정지하고, 입력이
  다시 감지되면 자동으로 재개하는 메커니즘이 없었다.
- 판정: 기존 버그 복구가 아니라 기존 의도에 없던 사용자 기능이므로
  `release/v0.28.0`에서 제공한다.

## 동작 계약

- `GetLastInputInfo` 기반 `WorktimeActivityWatcher`가 일정 주기(`root.after`
  폴링)로 마지막 입력 tick 변화를 감지한다. raw keyboard/mouse hook은 설치하지
  않는다.
- tick이 변하지 않은 채 설정된 무입력 시간(기본 5분, 1~120분)이 지나면
  `idle_callback`이 idle crossing마다 정확히 한 번 발생한다. 다음 입력에서
  보고가 재무장된다.
- 진행 중인 초과근무가 있으면 idle 감지 시점에 `paused_at`을 그 시각으로 기록해
  자동 일시정지한다. 일시정지 시점부터 정지 시간이 누적되며, 감지 지연분은
  근무시간에 포함된다.
- `pause_auto` 표시는 상태 파일에 저장된다(state version 4). v3 이전 상태의
  열린 일시정지는 모두 수동으로 취급해 입력으로 자동 재개하지 않는다.
- 자동 일시정지(`pause_auto=True`) 중 입력이 감지되면 `resume`으로 누적
  정지 시간을 확정하고 측정을 재개한다. 수동 일시정지(`pause_auto=False`)는
  입력이 와도 재개하지 않고 패널의 다시 시작이 필요하다.
- 자동 일시정지·재개 실패는 팝업 없이 로그만 남긴다(입력 이벤트마다 오류를
  표시하지 않는다).
- 패널과 툴팁은 자동 일시정지를 "자동 일시정지"로 구분해 표시하고, 입력 감지
  시 자동 재개됨을 안내한다.
- 설정의 "무입력 시 초과근무 자동 일시정지"를 끄면 새 자동 일시정지가 발생하지
  않는다. 이미 자동 일시정지된 타이머는 입력 감지 시 그대로 자동 재개된다.
  일시정지가 자동인지 수동인지는 `pause_auto` 표시가 기록하므로 설정을 끈
  뒤에도 자동 일시정지된 상태가 수동 일시정지로 바뀌지 않는다.

## 검증 범위

- `OvertimeStateStore.pause(automatic=True)`가 `pause_auto`를 기록하고
  `resume`이 지우며, v3 파일이 `pause_auto=False`로 승격되는 것을 단위
  테스트로 검증한다.
- watcher의 idle crossing 1회 보고·재무장·비활성 경로와 stop/reset_baseline
  초기화를 단위 테스트로 검증한다.
- Wrike 핸들러가 자동 일시정지만 입력으로 재개하고 수동 일시정지는 유지하는
  것, 비활성 설정에서 idle 콜백이 no-op인 것을 단위 테스트로 검증한다.
- 패널 상태 텍스트와 dataclass 검증(`auto_paused`는 `paused` 필요)을 단위
  테스트로 검증한다.
- 설정 카드의 새 필드는 코드 검토로 확인한다. 설정 화면은 변경 subset 검증이나
  실제 창 실행 없이 저장/로드 경로의 단위 증거로 대체한다.
